# 레거시 파일·이미지 제공

- 그룹 시스템 마이그레이션에서는 레거시 기록의 HTML 원문을 유지하며, 본문의 `/file/...`·`/image/...` 경로를 `app.khlug.org`에서 제공한다.
- 기존 파일과 파일 메타데이터는 Spring 백엔드로 이전하지 않는다. `app.khlug.org/file/...`·`app.khlug.org/image/...` 요청은 Spring 서버가 `khlug.org`의 같은 경로로 폴백하여 처리한다.
- 폴백은 임시 조치이며, 최종 제공 방식은 서버 관리자가 결정한다. 다음은 선택 가능한 방안의 예시다.
- **예시 1 — 신규 시스템 파일 URL 사용:** 프런트는 기록 렌더링 시 기존 파일 참조를 조회 응답의 `files[].url`로 받은 Presigned GET URL로 치환한다. 백엔드는 기존 파일과 메타데이터를 이전하여 신규 파일 제공 방식으로 처리하며, 메타데이터는 별도로 관리하거나 신규 파일 테이블에 병합할 수 있다. 읽기 URL은 [파일 매핑 계약](../plans/group/global.md#조회-응답의-파일-매핑)을 따른다.
- **예시 2 — 기존 경로 유지:** 프런트는 `/file/...`·`/image/...`로 요청하고, Spring 서버는 레거시 서버로부터 이전한 파일과 메타데이터를 사용해 해당 경로에서 직접 제공한다.
