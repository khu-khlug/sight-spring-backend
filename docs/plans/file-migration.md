# 레거시 파일 테이블 유지와 Spring 제공 전환

## 범위

`khlug_files`에는 그룹뿐 아니라 사이트 전체의 파일 메타데이터가 섞여 있다. 기존 테이블과 데이터를 Spring에서 사용할 수 있도록 가져와 유지하고 임시 읽기 URL 캐시 컬럼만 추가한다. 이미 같은 DB를 사용한다면 기존 테이블을 그대로 사용한다. 신규 `file_upload`와 병합하거나 그룹 관련 행만 선별해 옮기지 않는다.

## 데이터 유지

- 기존 `article`·`author`·`original`·`name`·`extension`·`mime`·`size`·`type`·`count_download`·생성·수정 시각을 모두 보존한다. 기존 테이블에 없는 PK나 신규 업로드 ID를 부여하지 않는다.
- R2 객체와 키, 기존 HTML의 파일 주소를 유지한다. 운영자는 실제 버킷·접두사·스토리지 접근 설정을 Spring에 연결한다.
- 레거시 파일을 옮기기 위해 신규 `file_upload`·`khlug_group_file`·`khlug_group_record_file` 행이나 카드·활동보고의 신규 파일 ID 참조를 만들지 않는다. 레거시 파일 조회와 첨부 목록은 기존 테이블의 소속 정보를 사용한다.
- 신규 업로드는 기존 신규 설계를 따른다. 레거시 구분용 JSON 컬럼과 신규 발급 경로·완료 표시·확인 예약을 레거시에 추가하지 않는다.
- 레거시 테이블과 객체는 신규 업로드의 확인 예약·미사용·참조 부재 청소 대상에서 제외한다. 신규 연결 행이 없다는 이유로 삭제하지 않는다.

## 임시 읽기 URL 캐시

- `khlug_files`에 `read_url TEXT NULL`과 `read_url_expires_at TIMESTAMP(6) NULL`만 추가한다. 기본값은 null이며 만료 시각은 UTC다.
- 권한 검사 후 유효한 캐시를 재사용한다. 캐시가 없거나 만료까지 1분 이하이면 7일 유효 Presigned GET URL을 발급해 두 컬럼을 함께 갱신한다.
- 캐시 갱신은 파일 자체의 수정이 아니므로 기존 `updated_at`을 변경하지 않는다. 기존 메타데이터·참조와 파일 키는 유지한다.
- 파일명·MIME·다운로드 정책이 바뀌면 캐시를 무효화한다. 리다이렉션 응답은 `private, no-store`이며 캐시 재사용 시에도 권한을 검사한다.

## 파일 제공

Spring의 `/file/{filename}`·`/image/{filename}`은 `khlug_files.name`으로 조회하고 기존 열람 정책을 적용한 뒤 Presigned GET URL로 302 리다이렉션한다. 레거시 테이블에는 전체 사이트 파일이 있으므로 그룹 파일이라고 가정하지 않는다. 기존 제공 코드의 소속·권한·쿼리 처리 기준은 운영자가 확인하여 Spring에서 유지한다.

신규 `/groups/{groupId}/files/{fileId}`는 신규 그룹 파일을 그룹 열람 권한으로 제공한다. 더 강한 권한의 파일은 각 기능 API에서 처리하며 활동보고는 기존 임시 읽기 주소 반환을 유지한다.

## 전환 순서

1. 운영자는 기존 테이블 전체를 Spring에서 조회할 수 있게 준비하고 원본 데이터·객체 키·스토리지 설정을 대조한다. 별도 DB로 복사한다면 전환 시점까지 변경분을 반영한다.
2. Spring에서 레거시 테이블을 사용하는 파일·이미지 API를 배포하고 기존 주소·권한·다운로드·미디어 제공을 확인한다.
3. Caddy에서 기존 도메인의 파일 경로를 Spring으로 전달한다. 다른 기능의 파일 요청도 기존대로 제공되는지 확인한다.
4. Laravel 종료는 사이트 전체 기능의 Spring 전환이 완료된 뒤 판단한다. 파일 테이블 분리·신규 테이블 통합도 전체 전환 이후 별도 작업으로 결정한다. 이번 작업에서는 기존 테이블을 유지한다.

운영 DB 이전과 실제 동작 확인은 담당자가 수행한다. 신규 기록의 영구 주소 저장 계약은 [그룹 공통 사항](group/global.md#기록-첨부-파일)을 따른다.
