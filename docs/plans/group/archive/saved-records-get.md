# 보관한 기록 목록 조회

보관한 기록 목록을 조회합니다. 요청자가 개인 보관함에 저장한 모든 그룹의 기록을 최근에 보관한 것부터 반환합니다. 현재 그룹이나 그룹 소속 여부로 필터링하지 않으며, 각 기록의 그룹 정보를 함께 반환합니다. 레거시 `User::group_record_saved()`와 `group/saved.blade.php`의 사용자 기준 보관함 동작을 유지합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
GET /saved-records
```

## 권한

USER (인증된 요청자 본인의 보관 목록만 조회)

## 조건

(해당 없음)

## 제한

- 한 번에 받는 기록 수는 최대 10개이며, 더 필요하면 `page`를 1 늘려 다시 요청해야 함
  - 10개인 이유: 기록 본문 전체를 담아 항목 하나가 무거우므로, 카드창의 기록 목록 조회와 같은 크기로 맞춤

## 부수 효과

(해당 없음)

## 쿼리스트링

| 이름   |    타입    | 기본값 | 설명                                         |
| :----- | :--------: | :----: | :------------------------------------------- |
| `page` | 숫자(uint) | 0 | 0부터 시작하는 페이지 번호. 페이지당 10개 |

페이지 크기는 10개로 고정하며, `page * 10`개를 건너뛴 위치부터 최대 10개를 반환한다. 첫 페이지는 `page=0`, 다음 페이지는 `page + 1`이다. `offset`과 `limit` 옵션은 받지 않는다.

## 요청 바디

(해당 없음)

## 성공 응답

```
200 OK
```

| 이름                 |    타입    | 설명                                                  |
| :------------------- | :--------: | :---------------------------------------------------- |
| `page` | 숫자(uint) | 조회한 페이지 번호 (요청의 `page`와 같음) |
| `totalCount`         | 숫자(uint) | 요청자의 전체 보관 기록 수. 삭제된 기록·삭제 카드의 기록도 포함 |
| `receivedCount`      | 숫자(uint) | 받은 기록 수 (`records` 길이)                         |
| `records`            | 객체 배열  | 기록 목록. 보관 일시 내림차순                         |
| `records.recordId`   | 10진 문자열 | 기록 아이디                                           |
| `records.type`       |    enum    | 본문 형식. `TIPTAP` \| `LEGACY`                       |
| `records.content`    |   문자열   | 기록 본문                                             |
| `records.groupId`    | 10진 문자열 | 기록이 속한 그룹 아이디                               |
| `records.groupName`  |   문자열   | 기록이 속한 그룹명                                    |
| `records.cardId`     |   10진 문자열   | 기록이 속한 카드 아이디                               |
| `records.cardTitle`  |   문자열   | 기록이 속한 카드명                                    |
| `records.isDeleted`  |   불리언   | 원본 기록 자체의 삭제 여부                            |
| `records.isCardDeleted` | 불리언 | 기록이 현재 속한 카드의 삭제 여부                     |
| `records.authorName` |   문자열   | 기록 작성자 실명                                      |
| `records.createdAt`  |   문자열   | 기록 작성 일시 (ISO 8601 UTC, `Z` 접미사)             |
| `records.savedAt`    |   문자열   | 보관 일시 (ISO 8601 UTC, `Z` 접미사)                  |

### 페이지네이션

다음 페이지는 `(page + 1) * 10 < totalCount`인 경우에만 남아 있다. 조회할 페이지의 시작 위치가 전체 개수 이상이면 빈 배열과 `receivedCount: 0`을 반환하고, `page`는 요청 값을 유지한다.

### 본문 반환 규칙

- `TIPTAP`·`LEGACY` 본문 모두 저장된 값을 그대로 반환한다. 서버는 본문을 파싱하거나 정제하지 않는다.
- 이 목록은 미리보기 용도이며 `files` 필드를 반환하지 않는다. 첨부 파일 연결 목록과 읽기 링크를 조회·발급하지 않는다.
- 클라이언트는 미리보기에서 본문의 첨부 파일을 표시하지 않는다. `files` 생략만으로 본문 안의 첨부 요소가 제거되는 것은 아니므로 표시 처리를 별도로 적용한다. 전체 기록의 첨부 파일은 기록 조회 API를 통해 확인한다.

## 정렬 동률 처리

보관 일시가 같으면 기록 아이디 내림차순이다. 페이지 연속성은 조회 사이 데이터 변경이 없는 경우를 기준으로 한다.

## 삭제된 원본과 보관 연결

- 원본 기록이나 현재 소속 카드가 삭제되어도 보관 연결이 있으면 목록과 `totalCount`에 포함한다. 삭제된 항목도 본문과 기존 소속 정보를 같은 응답 형식으로 반환한다.
- `isDeleted`는 원본 기록 자체의 삭제 여부, `isCardDeleted`는 현재 소속 카드의 삭제 여부다. 카드만 삭제되었다고 `isDeleted`를 true로 바꾸지 않는다.
- 프런트는 두 값 중 하나라도 true이면 해당 보관 기록 박스를 일반 항목보다 어둡게 표시한다. 둘 다 false이면 일반 표시한다. 삭제 시각·삭제 안내 문구·배지 등 추가적인 표시 정보는 제공하지 않으며, 응답에도 삭제 시각 필드를 추가하지 않는다.
- 삭제·복구는 보관 연결과 `savedAt`을 바꾸지 않는다. 복구 시 각 삭제 여부만 현재 상태에 맞게 반환하며, 두 값이 모두 false가 되면 일반 표시로 돌아간다. 정렬은 삭제·복구 여부와 관계없이 기존 보관 일시를 따른다. 비활성 카드도 포함하며, 비활성 상태만으로 삭제 상태를 표시하지 않는다.
- 삭제된 기록이나 삭제된 카드의 기록도 목록에서 보관 해제를 요청할 수 있다. 요청의 허용 여부는 [기록 개인 보관 변경](../card-window/group-record-archive.md)의 기존 권한·그룹 상태 조건을 따른다. 보관 해제 후에는 원본이 복구되어도 목록에 다시 나타나지 않는다.

## 테스트 케이스

1. 인증된 사용자는 모든 그룹에서 보관한 기록 목록을 조회할 수 있다
   - 200 응답과 함께 요청자가 모든 그룹에서 보관한 기록을 합쳐 보관 일시 내림차순으로 최대 10개 반환한다. 서로 다른 그룹의 기록이 함께 포함되며, 다른 회원이 보관한 기록은 포함하지 않는다
   - 본문은 `TIPTAP` JSON 문자열·`LEGACY` HTML을 그대로 반환하고, 현재 소속 그룹 아이디·이름, 카드 아이디·이름, 작성자 실명, 작성·보관 일시를 함께 반환한다
   - 기록·그룹·카드 아이디는 10진 문자열, 시각은 UTC ISO 8601 `Z` 형식이다
2. 첨부 파일 정보를 반환하지 않는다
   - 첨부 유무와 관계없이 각 기록에 `files` 필드가 없다. 파일 연결 목록 조회와 읽기 링크 발급을 수행하지 않는다
   - 본문 안의 파일 참조는 저장된 값 그대로 유지한다
3. 삭제된 원본도 목록에 포함하고 삭제 상태를 구분한다
   - 기록만 삭제되면 `isDeleted: true`, `isCardDeleted: false`, 카드만 삭제되면 `isDeleted: false`, `isCardDeleted: true`를 반환한다. 둘 다 삭제되면 두 값이 true이며, 둘 다 삭제되지 않았으면 두 값이 false다
   - 어느 경우에도 보관 연결이 있으면 본문과 기존 소속 정보를 반환하고 `totalCount`에 포함한다. 삭제 항목도 일반 항목과 같은 페이지네이션·정렬을 적용한다
   - 프런트는 두 값 중 하나라도 true이면 기록 박스를 어둡게 표시할 수 있으며, 삭제 시각 등 추가적인 표시 정보 없이 상태를 표현할 수 있다
   - 원본 기록·카드를 복구하면 각각의 삭제 여부를 갱신한다. 삭제·복구 전후의 `savedAt`, 목록 포함 여부와 `totalCount`는 유지한다
   - 비활성 카드의 기록은 계속 포함하며, 기록·카드가 삭제되지 않았다면 두 삭제 값은 false다
   - 삭제된 항목의 보관 해제는 개인 보관 변경 API의 기존 조건을 따른다. 해제에 성공하면 목록과 `totalCount`에서 빠지고, 이후 원본을 복구해도 다시 나타나지 않는다
4. 보관 일시가 같으면 아이디 순으로 정렬한다
   - 기록 아이디 내림차순이며, 페이지 경계에서도 누락·중복이 없다
5. `page`로 범위를 나눠 조회한다
   - 11개가 있으면 첫 응답은 10개, `page=1`이면 1개를 반환한다. `page * 10 >= totalCount`이면 빈 배열이다
   - 응답 `page`는 요청한 페이지 번호, `receivedCount`는 반환한 개수, `totalCount`는 모든 그룹을 합쳐 조회할 수 있는 보관 기록 수다
   - 음수·소수·숫자가 아닌 `page`는 400 에러를 반환한다
6. 그룹 상태와 소속 여부에 관계없이 조회할 수 있다
   - 중단·종료 그룹에서 보관한 기록과 현재 그룹원이 아닌 그룹에서 보관한 기록도 포함한다
   - 특정 그룹을 지정하지 않고 조회하며, 보관한 기록이 없으면 빈 배열과 `totalCount: 0`, `receivedCount: 0`을 반환한다
7. 인증된 사용자만 본인의 보관 목록을 조회할 수 있다
   - 인증되지 않으면 401 에러를 반환한다
   - 요청자의 보관 연결을 기준으로 조회하며 다른 사용자의 보관 목록은 조회할 수 없다
