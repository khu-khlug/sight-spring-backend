# 보관한 기록 목록 조회

보관한 기록 목록을 조회합니다. 요청자가 이 그룹에서 개인 보관함에 저장한 기록만 최근에 보관한 것부터 반환합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
GET /groups/:groupId/saved-records
```

## 권한

USER and 그룹원

## 조건

(해당 없음)

## 제한

- 한 번에 받는 기록 수는 최대 10개이며, 더 필요하면 `skip`을 늘려 다시 요청해야 함
  - 10개인 이유: 기록 본문 전체를 담아 항목 하나가 무거우므로, 카드창의 기록 목록 조회와 같은 크기로 맞춤

## 부수 효과

(해당 없음)

## 쿼리스트링

| 이름   |    타입    | 기본값 | 설명                                         |
| :----- | :--------: | :----: | :------------------------------------------- |
| `skip` | 숫자(uint) |   0    | 최근 보관한 기록부터 n개를 건너뛰고 반환     |

## 요청 바디

(해당 없음)

## 성공 응답

```
200 OK
```

| 이름                 |    타입    | 설명                                                  |
| :------------------- | :--------: | :---------------------------------------------------- |
| `skip`               | 숫자(uint) | 건너뛴 개수 (요청의 `skip`과 같음)                    |
| `totalCount`         | 숫자(uint) | 조회 가능한 보관 기록 총 수 (삭제된 기록·삭제 카드의 기록 제외) |
| `receivedCount`      | 숫자(uint) | 받은 기록 수 (`records` 길이)                         |
| `records`            | 객체 배열  | 기록 목록. 보관 일시 내림차순                         |
| `records.recordId`   | 숫자(Long) | 기록 아이디                                           |
| `records.type`       |    enum    | 본문 형식. `TIPTAP` \| `LEGACY`                       |
| `records.content`    |   문자열   | 기록 본문                                             |
| `records.cardId`     |   문자열   | 기록이 속한 카드 아이디                               |
| `records.cardTitle`  |   문자열   | 기록이 속한 카드명                                    |
| `records.authorName` |   문자열   | 기록 작성자 실명                                      |
| `records.createdAt`  |   문자열   | 기록 작성 일시 (ISO 8601 UTC, `Z` 접미사)             |
| `records.savedAt`    |   문자열   | 보관 일시 (ISO 8601 UTC, `Z` 접미사)                  |
| `records.files`      | 객체 배열  | 기록에 연결된 첨부 파일과 읽기 링크. 형식은 [기록 첨부 파일의 조회 응답 파일 매핑](../global.md#조회-응답의-파일-매핑)을 따름 |

### 본문 반환 규칙

- `TIPTAP`·`LEGACY` 본문 모두 저장된 값을 그대로 반환한다. 서버는 본문을 파싱하거나 정제하지 않는다.

## 정렬 동률 처리

보관 일시가 같으면 기록 아이디 내림차순이다. 페이지 연속성은 조회 사이 데이터 변경이 없는 경우를 기준으로 한다.

## 삭제된 원본과 보관 연결

보관 목록은 원본 기록 또는 현재 소속 카드가 삭제 상태이면 해당 기록을 응답과 totalCount에서 제외한다. 보관 연결은 유지하므로 원본과 카드가 모두 복구되면 기존 savedAt으로 다시 나타난다. 비활성 카드는 제외하지 않는다. 삭제 원본의 보관 해제는 개인 보관 변경 API의 조건에 따라 가능하며, 해제 후 복구해도 다시 나타나지 않는다.

## 테스트 케이스

1. 그룹원은 이 그룹에서 보관한 기록 목록을 조회할 수 있다
   - 200 응답과 함께 요청자가 이 그룹에서 보관한 기록만 보관 일시 내림차순으로 최대 10개 반환한다. 다른 회원이 보관한 기록은 포함하지 않는다
   - 본문은 `TIPTAP` JSON 문자열·`LEGACY` HTML을 그대로 반환하고, 현재 소속 카드 아이디·이름, 작성자 실명, 작성·보관 일시를 함께 반환한다
   - 기록 아이디는 숫자(Long), 카드·파일 아이디는 문자열, 시각은 UTC ISO 8601 `Z` 형식이다
2. 첨부 파일은 읽기 링크와 함께 반환한다
   - 첨부가 없으면 `files: []`다. 업로드가 끝난 파일은 7일 유효 읽기 링크를 주고, 업로드되지 않은 파일의 `url`은 null이다
3. 삭제된 원본은 목록에서 뺀다
   - 원본 기록이나 그 카드가 삭제되면 목록과 `totalCount`에서 뺀다. 둘 다 복구되면 기존 보관 일시로 다시 나타난다
   - 비활성 카드의 기록은 계속 보인다
   - 삭제된 원본의 보관을 해제한 뒤 원본을 복구하면 다시 나타나지 않는다
4. 보관 일시가 같으면 아이디 순으로 정렬한다
   - 기록 아이디 내림차순이며, 페이지 경계에서도 누락·중복이 없다
5. `skip`으로 범위를 나눠 조회한다
   - 11개가 있으면 첫 응답은 10개, `skip=10`이면 1개를 반환한다. `skip`이 전체 개수 이상이면 빈 배열이다
   - 응답 `skip`은 요청 값, `receivedCount`는 반환한 개수, `totalCount`는 조회할 수 있는 보관 기록 수다
   - 음수·소수·숫자가 아닌 `skip`은 400 에러를 반환한다
6. 그룹 상태와 관계없이 조회할 수 있다
   - 중단·종료 그룹에서도 그룹원이면 200 응답을 반환한다
7. 그룹원만 조회할 수 있다
   - 공개 그룹이라도 그룹원이 아니면 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
