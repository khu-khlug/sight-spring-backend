# 카드 커버 이미지 업로드 링크 발급

카드 커버로 사용할 이미지의 업로드 링크를 발급합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
POST /groups/:groupId/cards/:cardId/cover-image/upload-link
```

## 권한

USER and 그룹원

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함. 중단 상태에서는 발급하며 그룹 상태는 바꾸지 않음. [업로드 링크 발급의 중단 상태 예외](../global.md#중단-상태에서의-동작-제한)를 따름
- 카드가 삭제되지 않은 활성 상태여야 함. [카드 활성 상태별 동작](group-card-disabled-update.md#비활성-상태의-동작)을 따름

## 허용 형식

- `contentType`은 `image/jpeg`, `image/png`, `image/webp`, `image/gif`, `image/avif` 중 하나여야 한다.
- SVG(스크립트를 포함할 수 있음), HEIC(대부분 브라우저가 표시하지 못함), BMP·TIFF(크고 브라우저 지원이 약함)는 허용하지 않는다.
- 최대 크기와 링크 유효 시간은 [업로드 링크 기준](../global.md#업로드-링크-기준)을 따른다.

## 업로드 계약

- 발급만으로 커버가 변경되지는 않는다. 반환된 `url`로 PUT 업로드한 뒤 [커버 이미지 지정](group-card-cover-image-update.md)에 `fileUploadId`를 제출한다.
- 업로드된 파일은 [커버 이미지 지정의 파일 검증 흐름](group-card-cover-image-update.md#파일-검증-흐름-fileuploadid)으로 검증한다.

## 저장 처리

업로드 용도·발급자·대상 카드와 연결된 미사용 업로드 정보를 생성한다.

## 요청 바디

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `fileName` | 문자열 | 필수. 원본 파일명 |
| `contentType` | 문자열 | 필수. 이미지 MIME 타입 |

## 성공 응답

```
200 OK
```

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `url` | 문자열 | 파일을 PUT 업로드할 임시 주소 |
| `fileUploadId` | 문자열 | 커버 변경 시 제출할 업로드 아이디 |

## 실패 응답

[그룹 공통 실패 응답](../global.md#공통-실패-응답)을 함께 적용한다.

| 상황 | 응답 코드 |
| :-- | :--: |
| 종료된 그룹임 | 400 |
| 비활성 카드임 | 400 |
| 파일명 또는 MIME 타입이 없거나 허용 형식이 아님 | 400 |
| 삭제된 카드임 | 400 |

## 테스트 케이스

1. 그룹원은 커버 이미지 업로드 링크를 발급받을 수 있다
   - 파일명과 허용 MIME 타입을 보내면 200 응답과 함께 `url`과 `fileUploadId`를 반환한다
   - 업로드 용도·발급자·대상 카드가 연결된 미사용 업로드 기록을 만든다
   - 발급만으로는 카드 커버가 바뀌지 않는다
2. 허용한 이미지 형식만 발급한다
   - `image/jpeg`, `image/png`, `image/webp`, `image/gif`, `image/avif`는 발급한다
   - SVG·HEIC·BMP·TIFF 등 그 밖의 형식이나 파일명·MIME 타입이 없으면 400 에러를 반환한다
3. 업로드 링크는 정해진 기준을 따른다
   - PUT URL은 10분간 유효하고 파일 최대 크기는 20 MiB다
   - 링크 만료 시각에 1분을 더한 시점에 업로드 확인을 예약한다
4. 업로드되지 않은 파일은 확인 예약 시점에 정리한다
   - 미사용 파일의 R2 객체가 없으면 삭제 표시 후 업로드 기록을 정리한다. 객체가 있으면 미사용 업로드로 유지하고 주기적 청소 대상 규칙을 따른다
5. 중단된 그룹에서도 발급할 수 있다
   - 중단 그룹에서도 200 응답을 반환하며 그룹 상태는 바뀌지 않는다
6. 종료된 그룹에서는 발급할 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
7. 비활성·삭제된 카드에는 발급할 수 없다
   - 비활성 카드나 삭제된 카드면 400 에러를 반환한다
8. 그룹원만 발급받을 수 있다
   - 그룹원이 아니면 403, 인증되지 않으면 401 에러를 반환한다
9. 경로의 그룹·카드가 있어야 한다
   - 그룹이 없거나, 카드가 없거나 다른 그룹의 카드면 404 에러를 반환한다
10. 거부된 요청은 아무것도 바꾸지 않는다
    - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다. 업로드 기록과 확인 예약도 만들지 않는다
