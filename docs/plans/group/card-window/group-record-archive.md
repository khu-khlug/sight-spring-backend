# 기록 개인 보관 변경

요청자 본인의 기록 개인 보관 여부를 변경합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
PUT /groups/:groupId/records/:recordId/archive
```

## 권한

USER and 그룹원

기록 작성자가 아닌 그룹원도 요청할 수 있다.

## 조건

- 기록의 현재 소속 카드는 `recordId`로 조회하며, 해당 카드의 그룹이 `groupId`와 일치해야 함
- 그룹이 중단·종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- `isInUserArchive: true`이면 해당 기록과 그 기록이 현재 속한 카드가 모두 삭제 상태가 아니어야 함
- `isInUserArchive: false`이면 기록·카드의 삭제 여부나 카드 활성 여부는 제한하지 않음

카드 활성 상태와 중단 상태 제한은 [카드 활성 상태별 동작](group-card-disabled-update.md#비활성-상태의-동작)과 [그룹 공통 사항](../global.md#중단-상태에서의-동작-제한)을 따른다.

## 저장 처리

true이면 원본을 복제하지 않고 요청자와 기록의 연결을 저장한다. false이면 해당 연결만 제거하며 기록 자체는 삭제하지 않는다. 다른 회원의 보관 상태는 유지한다. 이미 보관한 기록의 보관 요청과 보관하지 않은 기록의 보관 해제는 변경 없이 성공하며 부수 효과를 반복하지 않는다.

## 실패 응답

[그룹 공통 실패 응답](../global.md#공통-실패-응답)을 함께 적용한다.

| 상황 | 응답 코드 |
| :-- | :--: |
| 중단되거나 종료된 그룹임 | 400 |
| `isInUserArchive`가 없거나 불리언이 아님 | 400 |
| 보관 추가 대상이 삭제된 기록이거나 삭제된 카드에 속함 | 400 |
| 기록이 없거나 다른 그룹의 기록임 | 404 |

## 테스트 케이스

1. 그룹원은 기록을 개인 보관함에 넣을 수 있다
   - `isInUserArchive: true`를 보내면 204 응답과 함께 원본을 복제하지 않고 요청자와 기록의 보관 연결만 저장한다. 작성자가 아니어도 된다
   - 실제로 바뀌면 요청자에게 보관 알림을 보낸다
2. 개인 보관을 해제할 수 있다
   - false를 보내면 204 응답과 함께 요청자의 연결만 지운다. 원본 기록과 다른 회원의 보관 상태는 그대로다
   - 실제로 바뀌면 요청자에게 보관 해제 알림을 보낸다
   - 기록·카드가 삭제됐거나 카드가 비활성이어도 해제할 수 있다
3. 현재와 같은 보관 상태로 요청하면 아무것도 바뀌지 않는다
   - 이미 보관한 기록의 보관, 보관하지 않은 기록의 해제는 204 응답을 반환하고 알림을 보내지 않는다
4. `isInUserArchive`는 불리언이어야 한다
   - 없거나 null이거나 불리언이 아니면 400 에러를 반환한다
5. 삭제된 기록은 보관함에 넣을 수 없다
   - 삭제된 기록이나 삭제된 카드의 기록을 보관하면 400 에러를 반환한다
6. 중단·종료된 그룹에서는 보관 상태를 바꿀 수 없다
   - 그룹이 `STOP`·`SUCCESS`·`FAIL` 상태면 보관·해제 모두 400 에러를 반환한다
7. 그룹원만 보관 상태를 바꿀 수 있다
   - 그룹원이 아니면 403, 인증되지 않으면 401 에러를 반환한다
8. 경로의 그룹·기록이 있어야 한다
   - 그룹이 없거나, 기록이 없거나 현재 소속 카드의 그룹이 경로 그룹과 다르면 404 에러를 반환한다. 보관 해제에서도 같다
9. 거부된 요청은 아무것도 바꾸지 않는다
   - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다
