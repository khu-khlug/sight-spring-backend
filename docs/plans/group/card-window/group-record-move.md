# 기록 소속 카드 변경

기록을 같은 그룹의 다른 카드로 이동합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
PUT /groups/:groupId/records/:recordId/position
```

## 권한

USER and 그룹원

## 조건

- 기록의 현재 소속 카드는 `recordId`로 조회하며, 해당 카드의 그룹이 `groupId`와 일치해야 함
- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- 원본·목적지 카드가 모두 같은 그룹의 삭제되지 않은 활성 카드여야 함. [카드 활성 상태별 동작](group-card-disabled-update.md#비활성-상태의-동작)을 따름
- 삭제된 기록이 아니어야 함
- 목적지 카드가 현재 카드와 같으면 변경 없이 성공함

## 저장 처리

- 기록 아이디·작성자·본문·작성 시각·포인트는 유지한다. 개인 보관 기록은 같은 기록을 계속 가리킨다.
- 소속 카드 변경과 양쪽 카드의 기록 수 변경은 하나의 트랜잭션에서 처리한다. 그룹의 전체 기록 수는 바뀌지 않는다.

## 부수 효과

실제 변경이 발생하면 중단 상태를 진행 중으로 자동 전환한다. [그룹 공통 사항](../global.md#활동에-따른-중단-상태-해제)을 따른다.

## 실패 응답

[그룹 공통 실패 응답](../global.md#공통-실패-응답)을 함께 적용한다.

| 상황 | 응답 코드 |
| :-- | :--: |
| 종료된 그룹임 | 400 |
| 원본 또는 목적지 카드가 비활성 상태임 | 400 |
| 목적지 카드가 이 그룹에 없거나 삭제됨 | 400 |
| 기록이 삭제 상태임 | 400 |
| 원본 카드가 삭제됨 | 400 |

## 테스트 케이스

1. 그룹원은 기록을 같은 그룹의 다른 카드로 옮길 수 있다
   - `targetCardId`를 보내면 204 응답과 함께 소속 카드를 바꾼다
   - 원본 카드의 기록 수는 1 줄고 목적지 카드는 1 늘며, 그룹의 전체 기록 수는 그대로다. 소속 변경과 두 카드의 기록 수 변경은 함께 반영된다
   - 기록 아이디·작성자·본문·첨부 파일·작성 시각·포인트는 그대로이고, 개인 보관 연결도 같은 기록을 가리킨다
   - 기록 이동 로그를 남기고 최근 활동 일시를 갱신한다
2. 현재 카드로 옮기면 아무것도 바뀌지 않는다
   - 목적지가 현재 카드면 204 응답을 반환하고 로그를 남기지 않는다
3. 목적지 카드는 이 그룹의 활성 카드여야 한다
   - `targetCardId`가 없거나 문자열이 아니면 400 에러를 반환한다
   - 목적지 카드가 없거나, 다른 그룹 카드이거나, 삭제·비활성 카드면 400 에러를 반환한다
4. 삭제된 기록은 옮길 수 없다
   - 삭제된 기록이면 400 에러를 반환한다
5. 종료된 그룹에서는 기록을 옮길 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
6. 중단된 그룹에서 기록을 옮기면 그룹이 다시 진행 중이 된다
   - 실제로 옮겨지면 그룹 상태가 `PROGRESS`로 전환된다
7. 비활성·삭제된 카드의 기록은 옮길 수 없다
   - 원본 카드가 비활성이거나 삭제됐으면 400 에러를 반환한다
8. 그룹원만 기록을 옮길 수 있다
   - 그룹원이 아니면 403, 인증되지 않으면 401 에러를 반환한다
9. 경로의 그룹·기록이 있어야 한다
   - 그룹이 없거나, 기록이 없거나 현재 소속 카드의 그룹이 경로 그룹과 다르면 404 에러를 반환한다
10. 거부된 요청은 아무것도 바꾸지 않는다
    - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다
