# 그룹 채팅 메시지 목록 조회

그룹 채팅방(디스코드 채널)의 메시지를 `before` 커서로 거슬러 올라가며 한 번에 최대 50개 조회합니다.

Discord 봇으로 조회하며 백엔드에서는 채팅 내용을 캐싱하지 않습니다. 연동 방식과 캐시 정책은 [채팅 API 공통 사항](global.md)을 따릅니다.

Discord 채널 URL과 채팅방 존재·참여 여부는 [그룹 정보 조회](../info/group-info-get.md#discord-채널-바로가기)의 응답을 사용합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
GET /groups/:groupId/chat-messages
```

## 권한

USER and 그룹원

## 조건

- 그룹에 채팅방이 있어야 함

## 제한

- 반환 크기는 최대 50개로 고정하며, 이전 메시지는 응답의 `nextBefore`를 다음 요청의 `before`로 보내 조회한다.
- `before`를 생략하면 최신 메시지부터 조회한다. 지정하면 해당 메시지 ID보다 이전 메시지만 조회하며 기준 메시지 자체는 포함하지 않는다.
- Discord의 메시지 ID 커서를 그대로 사용한다. 새 메시지가 도착해도 이전 메시지를 이어 읽는 경계가 밀리지 않으며, 최신 메시지부터 앞 페이지들을 반복 조회하지 않는다.

## 새니타이징

- Discord 응답에서 받은 `attachments.url`이 디스코드 첨부 파일 주소(`https://cdn.discordapp.com/...` 등)인지 검증한다. 검증한 첨부 파일 주소만 반환한다.

## 부수 효과

## 쿼리스트링

| 이름   |    타입    | 기본값 | 설명                                                  |
| :----- | :--------: | :----: | :---------------------------------------------------- |
| `before` | 문자열 | 생략 | 이 Discord 메시지 ID보다 이전 메시지를 조회. 양의 64비트 정수 범위의 10진수 snowflake 문자열 |

첫 조회에는 `before`를 보내지 않는다. 이후에는 이전 응답의 `nextBefore`를 문자열 그대로 사용한다. 빈 문자열·음수·소수·숫자가 아닌 값·64비트 정수 범위를 벗어난 값은 400으로 거부하며 Discord를 호출하지 않는다. `page`, `offset`, `limit`, `after`, `around` 옵션은 받지 않는다.

(해당 없음)

## 성공 응답

```
200 OK
```

| 이름                               |      타입      | 설명                                                                    |
| :--------------------------------- | :------------: | :---------------------------------------------------------------------- |
| `nextBefore` | 문자열 \| null | 다음 요청의 `before`. 이전 메시지가 더 있으면 이번 응답의 가장 오래된 메시지 ID, 없으면 null |
| `receivedCount`                    |   숫자(uint)   | 받은 메시지 수 (`messages` 길이)                                        |
| `hasMore`                          |     불리언     | 이보다 이전 메시지가 더 있는지                                          |
| `messages`                         |   객체 배열    | 메시지 목록. 오래된 메시지가 앞, 최신 메시지가 뒤                       |
| `messages.id`                      |     문자열     | 메시지 아이디                                                           |
| `messages.authorName`              |     문자열     | 작성자 표시 이름. HTML로 해석하지 않는 일반 텍스트 |
| `messages.content`                 |     문자열     | 메시지 본문. HTML로 해석하지 않는 일반 텍스트 |
| `messages.createdAt`               |     문자열     | 작성 일시 (ISO 8601 UTC, `Z` 접미사)                                    |
| `messages.attachments`             |   객체 배열    | 첨부 파일 목록. 없으면 빈 배열                                          |
| `messages.attachments.name`        |     문자열     | 파일 이름                                                               |
| `messages.attachments.contentType` | 문자열 \| null | MIME 타입                                                               |
| `messages.attachments.size`        |   숫자(uint)   | 파일 크기 (바이트)                                                      |
| `messages.attachments.url`         |     문자열     | 파일을 내려받을 수 있는 주소                                            |

### 페이지네이션

- `hasMore: true`이면 `nextBefore`를 다음 요청의 `before`로 보낸다. 응답 배열은 오래된 순이므로 `nextBefore`는 `messages[0].id`와 같다. `hasMore: false`이면 `nextBefore`는 null이다.
- 기준보다 이전 메시지가 없으면 `messages: []`, `receivedCount: 0`, `hasMore: false`, `nextBefore: null`을 반환한다. 요청한 범위에 정확히 50개만 있어도 `hasMore: false`다.
- 서버는 Discord의 `GET /channels/{channelId}/messages`에 요청의 `before`와 `limit=51`을 전달한다. 첫 조회에서는 Discord 요청에서도 `before`를 생략한다.
- Discord가 최신순으로 준 결과 중 앞의 최대 50개를 응답 대상으로 고른다. 51번째 메시지가 있으면 `hasMore: true`이며, 이 메시지는 응답에 넣지 않고 다음 조회에 포함되도록 한다. 선택한 최대 50개를 오래된 순으로 정렬해 반환한다.
- 메시지 ID는 프런트와 백엔드 사이에서 문자열로 유지한다. 프런트가 JavaScript `Number`로 변환해 정밀도를 잃지 않도록 한다.
- 연동 계약은 [Discord Get Channel Messages](https://docs.discord.com/developers/resources/message#get-channel-messages)를 따른다. 51개 조회는 Discord의 최대 100개 제한 안에서 본문과 이전 메시지 존재 여부를 한 번의 요청으로 확인하기 위한 내부 처리다.

## 실패 응답

| 상황                   | 응답 코드 |
| :--------------------- | :-------: |
| 그룹에 채팅방이 없음   |    400    |
| `before` 형식이 잘못됨 | 400 |

## 외부 실패 처리

Discord의 권한 상실(401/403), 채널 없음(404), 호출 제한(429), 5xx·네트워크 오류·타임아웃은 502로 응답한다. SIGHT의 권한/입력 오류와 구분하며 Discord 오류 본문·토큰을 노출하지 않는다. Discord 조회에 실패하면 정상적인 빈 목록으로 대체하지 않는다.

## 테스트 케이스

1. 그룹원은 채팅방 메시지를 조회할 수 있다
   - 200 응답과 함께 최신 메시지부터 최대 50개를 고르고, 응답 배열은 그 범위를 오래된 순으로 정렬한다
   - 메시지 아이디는 문자열이고, 작성자 이름과 본문은 HTML로 해석하지 않는 일반 텍스트다. 시각은 UTC ISO 8601 `Z` 형식이다
2. 첨부 파일은 검증한 주소만 반환한다
   - 첨부가 없으면 빈 배열, MIME 타입이 없으면 `contentType: null`이다. Discord 첨부 파일 주소로 확인된 URL만 반환한다
3. `before`로 이전 메시지를 이어서 조회한다
   - 메시지가 51개면 첫 응답은 최신 50개, `hasMore: true`, 응답의 가장 오래된 ID인 `nextBefore`를 반환한다. 이 ID를 `before`로 요청하면 가장 오래된 1개와 `hasMore: false`, `nextBefore: null`을 반환한다
   - `before`에 해당하는 메시지는 응답에 포함하지 않는다. 첫 조회 후 새 메시지가 도착해도 같은 커서로 이전 기록을 조회하면 새 메시지 때문에 경계가 밀리거나 앞 응답의 메시지가 중복되지 않는다
   - 전체 메시지가 0·49·50개이면 첫 응답의 `hasMore`는 false, `nextBefore`는 null이다. 요청한 커서보다 이전 메시지가 없으면 빈 배열과 `receivedCount: 0`을 반환한다
   - 각 SIGHT 조회는 요청한 `before`로 Discord를 한 번 조회하며 최신 메시지부터 반복해서 건너뛰지 않는다
   - 빈 문자열·음수·소수·숫자가 아닌 값·범위를 벗어난 `before`는 400이며 Discord를 호출하지 않는다. 응답 커서와 메시지 ID는 문자열이다
4. 메시지는 매번 Discord에서 읽는다
   - 같은 범위를 다시 조회해도 Discord 봇으로 원본을 읽으며, 메시지를 서버에 캐시하지 않는다
5. Discord 오류는 502다
   - Discord 401/403·404·429·5xx·연결 오류·타임아웃이면 502 에러를 반환한다. 실패를 빈 목록으로 대체하지 않으며, 오류 원문과 인증 정보는 노출하지 않는다
6. 채팅방이 있어야 한다
   - 그룹에 채팅방이 없으면 400 에러를 반환하고 Discord를 호출하지 않는다
7. 그룹 상태와 관계없이 조회할 수 있다
   - 중단·종료 그룹에서도 그룹원이면 200 응답을 반환한다
8. 그룹원만 조회할 수 있다
   - 공개 범위와 관계없이 그룹원이 아니면 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
