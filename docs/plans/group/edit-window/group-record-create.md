# 카드 기록 작성

카드에 새 활동 기록을 작성합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
POST /groups/:groupId/cards/:cardId/records
```

## 권한

USER and 그룹원

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- 카드가 삭제되지 않은 활성 상태여야 함. [카드 활성 상태별 동작](../card-window/group-card-disabled-update.md#비활성-상태의-동작)을 따름
- 본문(`content`)이 빈 문자열이 아니어야 함. 서버는 본문을 파싱하지 않으므로 본문 안의 내용 유무는 확인하지 않음
- 본문 크기는 UTF-8 바이트 기준 최대 1 MiB(1,048,576바이트)여야 함. 첨부 파일 크기는 포함하지 않음
- 첨부 파일 배열(`files`)은 [기록 첨부 파일](../global.md#기록-첨부-파일)의 비교 규칙을 따름. 새 기록이므로 비교 대상 연결 목록은 비어 있음

## 생성 기본값

| 항목 | 기본값 |
| :-- | :-- |
| 작성자 | 요청자 |
| `type` | `TIPTAP` |
| `isDeleted` | false |
| `isInPortfolio` | true |

## 저장 처리

- 카드·그룹의 기록 수를 증가시킨다.
- `files` 배열로 새 기록의 연결 목록을 만든다. 새 파일은 업로드 링크를 발급하고, 기존 파일은 참조를 추가한다.
- 기록 저장이 성공하면 요청자의 임시저장을 지운다. 임시저장에 연결돼 있던 파일 중 요청 배열에 같은 `fileId`로 들어온 파일은 새 기록에 연결되므로 유지되고, 연결이 하나도 남지 않은 파일은 삭제한다. [기록 첨부 파일의 임시저장과 기록 저장 사이의 처리](../global.md#임시저장과-기록-저장-사이의-처리)를 따른다.

## 부수 효과

### 그룹 상태

실제 변경이 발생하면 중단 상태를 진행 중으로 자동 전환한다. [그룹 공통 사항](../global.md#활동에-따른-중단-상태-해제)을 따른다.

### 경험치 변동

| 대상 | 변동 |
| :-- | :--: |
| 기록을 작성한 요청자 | +2 |

### 알림

그룹원 전체에게 기록 작성 알림

### 그룹 활동 로그

그룹 활동 로그에 기록 작성을 기록하고 최근 활동 일시를 갱신함

## 쿼리스트링

(해당 없음)

## 요청 바디

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `content` | 문자열 | 필수. TIPTAP 문서 JSON을 직렬화한 문자열 |
| `files` | 객체 배열 | 필수. 본문이 참조하는 파일 전체. 형식은 [요청의 파일 식별자 배열](../global.md#요청의-파일-식별자-배열)을 따름 |

## 성공 응답

```
201 Created
```

생성된 기록을 [기록 필드](group-record-get.md#기록-필드) 형식으로 반환하고, 아래 필드를 함께 반환한다.

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `uploads` | 객체 배열 | 새 파일의 업로드 정보. 형식은 [기록 첨부 파일의 비교 규칙](../global.md#비교-규칙)을 따름 |

## 실패 응답

[그룹 공통 실패 응답](../global.md#공통-실패-응답)을 함께 적용한다.

| 상황 | 응답 코드 |
| :-- | :--: |
| 종료된 그룹임 | 400 |
| 비활성 카드임 | 400 |
| 본문이 빈 문자열이거나 1 MiB를 초과함 | 400 |
| `files` 형식이 잘못됨 (필수 값 누락, 식별자 중복, 최대 크기 초과) | 400 |
| `files`가 다른 그룹의 파일이나 존재하지 않거나 삭제된 파일을 참조함 | 400 |
| 삭제된 카드임 | 400 |

## 테스트 케이스

1. 그룹원은 카드에 기록을 작성할 수 있다
   - 본문과 `files`를 보내면 201 응답과 함께 생성된 기록과 `uploads`를 반환한다
   - 작성자는 요청자, `type`은 `TIPTAP`, `isDeleted`는 false, `isInPortfolio`는 true다
   - 카드·그룹의 기록 수를 1 늘리고, 요청자에게 +2 exp를 지급한다
   - 그룹원 전체에게 기록 작성 알림을 보내고, 기록 작성 로그를 남기고 최근 활동 일시를 갱신한다
2. 본문은 비어 있지 않은 UTF-8 1 MiB 이하 문자열이다
   - 빈 문자열이면 400 에러를 반환한다. 서버는 본문을 파싱하지 않으므로 표시할 내용이 있는지는 검사하지 않는다
   - 1,048,576바이트는 저장하고 그보다 크면 400 에러를 반환한다. 첨부 파일 크기는 본문 크기에 더하지 않는다
3. 새 파일에는 업로드 링크를 발급한다
   - `fileId: null`인 항목마다 업로드 기록·연결·업로드 확인 예약을 만들고, `uploads`에 `id`·`fileId`·10분 유효 PUT URL을 반환한다
   - 새 파일이 없으면 `uploads: []`이고, `files: []`면 파일 연결 없이 저장한다
4. 같은 그룹의 기존 파일은 참조로 연결한다
   - 같은 그룹의 파일을 새 식별자로 보내면 다시 업로드하지 않고 연결만 추가한다
   - 다른 그룹 파일·없는 파일·삭제 표시된 파일을 참조하면 400 에러를 반환하고, 같은 요청의 다른 항목도 저장하지 않는다
5. `files` 항목은 정해진 형식이어야 한다
   - `files`가 없거나, 항목의 `id`가 없거나 중복되거나, 새 파일의 `name`·`size`·`contentType`이 없거나 타입이 잘못되면 400 에러를 반환한다
   - 파일 하나는 20 MiB까지 허용하고, 음수·소수·20 MiB 초과 크기는 400 에러를 반환한다
6. 작성이 성공하면 요청자의 임시저장을 지운다
   - 임시저장의 파일을 같은 `fileId`로 넘겨받으면 유지하고, 연결이 하나도 남지 않은 파일만 삭제 표시한 뒤 커밋 후 R2에서 지운다
7. 종료된 그룹에서는 기록을 작성할 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
8. 중단된 그룹에서 기록을 작성하면 그룹이 다시 진행 중이 된다
   - 그룹 상태가 `PROGRESS`로 전환된다
9. 비활성·삭제된 카드에는 기록을 작성할 수 없다
   - 비활성 카드나 삭제된 카드면 400 에러를 반환한다
10. 그룹원만 기록을 작성할 수 있다
    - 그룹원이 아니면 403, 인증되지 않으면 401 에러를 반환한다
11. 경로의 그룹·카드가 있어야 한다
    - 그룹이 없거나, 카드가 없거나 다른 그룹의 카드면 404 에러를 반환한다
12. 커밋 후 R2 삭제가 실패해도 요청은 성공한다
    - 성공 응답을 유지하고 삭제 표시를 남겨 청소에서 다시 지운다. `NoSuchKey`는 삭제 성공, `NoSuchBucket`은 다시 처리할 대상이다
13. 서버는 본문과 첨부 목록을 비교하지 않는다
    - 본문의 블록과 `files`가 달라도 본문을 파싱해 비교하지 않고 `files`로 연결 목록을 만든다
14. 응답 필드는 정해진 타입이다
    - 기록 아이디는 숫자(Long), 파일 아이디는 문자열, 작성·수정 일시는 UTC ISO 8601 `Z` 형식이다
15. DB 처리가 실패하면 모두 되돌린다
    - 트랜잭션 도중 실패하면 기록·파일 연결·업로드 기록·임시저장·경험치·알림·로그를 함께 되돌리고, R2 객체는 지우지 않는다
16. 거부된 요청은 아무것도 바꾸지 않는다
    - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다
