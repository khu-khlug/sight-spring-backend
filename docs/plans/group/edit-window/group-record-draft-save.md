# 기록 임시저장 저장

요청자의 기록 임시저장을 저장합니다. 임시저장은 회원당 하나뿐이며, 저장하면 기존 임시저장을 대체합니다. 첨부 파일 배열을 함께 받아 새 파일의 업로드 링크를 발급합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
PUT /groups/:groupId/records/draft
```

## 권한

USER and 그룹원

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- 중단 상태에서는 실행할 수 없음. [그룹 공통 사항의 중단 상태 동작 제한](../global.md#중단-상태에서의-동작-제한)을 따름
- `cardId`가 이 그룹의 삭제되지 않은 카드여야 함
- `recordId`를 보내면 그 기록이 `cardId` 카드의 삭제되지 않은 `TIPTAP` 기록이고 요청자가 작성자여야 함. `LEGACY` 기록은 수정할 수 없으므로 임시저장도 만들 수 없음
- 본문(`content`) 크기는 UTF-8 바이트 기준 최대 1 MiB(1,048,576바이트)여야 함
- 요청의 `updatedAt`이 서버에 저장된 요청자의 임시저장의 `updatedAt`보다 이르면 저장하지 않음
- 첨부 파일 배열(`files`)은 [기록 첨부 파일](../global.md#기록-첨부-파일)의 비교 규칙을 따름. 비교 대상은 같은 그룹·같은 대상(`cardId`·`recordId`)의 기존 임시저장 연결 목록이며, 기존 임시저장이 다른 대상이면 빈 목록과 비교함

## 저장 처리

- 기존 임시저장이 다른 그룹이거나 다른 대상(`cardId`·`recordId`)이면 기존 임시저장의 연결을 모두 해제하고, 연결이 하나도 남지 않은 파일은 삭제한다.
- 임시저장 본문은 그대로 저장한다. 서버는 본문을 파싱하지 않는다.
- 기존 기록을 수정 중인 임시저장은 그 기록과 같은 기록 파일 식별자 공간을 쓴다.

## 요청 바디

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `cardId` | 문자열 | 필수. 작성 중인 기록이 속한 카드 아이디 |
| `recordId` | 숫자(Long) \| null | 필수. 수정 중인 기록 아이디. 새 기록 작성 중이면 null |
| `content` | 문자열 | 필수. TIPTAP 문서 JSON을 직렬화한 문자열 |
| `files` | 객체 배열 | 필수. 본문이 참조하는 파일 전체. 형식은 [요청의 파일 식별자 배열](../global.md#요청의-파일-식별자-배열)을 따름 |
| `updatedAt` | 문자열 | 필수. 클라이언트에서 임시저장 내용을 마지막으로 수정한 일시. [그룹 공통 시각 표기](../global.md#그룹-api-시각-표기-utc)를 따름 |

## 성공 응답

```
200 OK
```

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `uploads` | 객체 배열 | 새 파일의 업로드 정보. 새 파일이 없으면 빈 배열. 형식은 [기록 첨부 파일의 비교 규칙](../global.md#비교-규칙)을 따름 |

## 실패 응답

[그룹 공통 실패 응답](../global.md#공통-실패-응답)을 함께 적용한다.

| 상황 | 응답 코드 |
| :-- | :--: |
| 중단되거나 종료된 그룹임 | 400 |
| `cardId`가 이 그룹의 카드가 아니거나 `recordId`가 그 카드의 기록이 아님 | 400 |
| `recordId`가 `LEGACY` 기록임 | 400 |
| 본문이 1 MiB를 초과함 | 400 |
| `files` 형식이 잘못됨 (필수 값 누락, 식별자 중복, 최대 크기 초과) | 400 |
| 이미 연결된 식별자에 다른 `fileId`를 보냄 | 400 |
| `files`가 다른 그룹의 파일이나 존재하지 않거나 삭제된 파일을 참조함 | 400 |
| 수정 중인 기록의 작성자가 아님 | 403 |
| 삭제된 카드·기록임 | 400 |
| 서버에 더 최신 임시저장이 있음 | 409 |

## 테스트 케이스

1. 그룹원은 기록 임시저장을 저장할 수 있다
   - `cardId`·`recordId`·본문·`files`·`updatedAt`을 보내면 200 응답과 함께 `uploads`를 반환한다
   - 임시저장은 회원당 하나이며 저장하면 기존 임시저장을 대체한다
2. 본인이 작성한 기록의 수정 내용도 임시저장할 수 있다
   - `recordId`에 이 카드의 본인 `TIPTAP` 기록을 보내면 저장한다
   - 다른 작성자의 기록이면 403, 다른 카드의 기록이나 `LEGACY` 기록이면 400 에러를 반환한다
3. 서버에 더 최신 임시저장이 있으면 저장하지 않는다
   - 요청 `updatedAt`이 서버 값보다 이르면 409 에러를 반환하고 기존 임시저장을 그대로 둔다. 같거나 늦으면 저장한다
   - `updatedAt`이 없거나 UTC ISO 8601 `Z` 형식이 아니면 400 에러를 반환한다
4. 본문은 UTF-8 1 MiB 이하 문자열이다
   - 1,048,576바이트는 저장하고 그보다 크면 400 에러를 반환한다. 서버는 본문을 파싱하지 않는다
5. 새 파일에는 업로드 링크를 발급한다
   - `fileId: null`인 항목마다 업로드 기록·연결·확인 예약을 만들고 `uploads`에 10분 유효 PUT URL을 반환한다. 새 파일이 없으면 `uploads: []`다
6. 같은 대상의 기존 임시저장과 연결 목록을 비교한다
   - 같은 `id`·`fileId`는 유지하고, 빠진 연결은 해제한다. `files: []`면 모든 연결을 해제한다
   - 이미 연결된 `id`에 다른 `fileId`를 보내면 400 에러를 반환한다
   - 기존 임시저장이 다른 그룹이거나 다른 대상(`cardId`·`recordId`)이면 기존 연결을 모두 해제하고 빈 목록과 비교한다
7. 연결이 하나도 남지 않은 파일은 삭제한다
   - 삭제 표시 후 커밋하고 R2에서 지운다. 다른 기록·임시저장에 연결이 남은 파일은 유지한다
8. 참조하는 파일과 `files` 항목은 올바라야 한다
   - 다른 그룹 파일·없는 파일·삭제 표시된 파일을 참조하면 400 에러를 반환하고, 같은 요청의 다른 항목도 저장하지 않는다
   - `id`가 없거나 중복되거나, 새 파일 메타데이터가 없거나 잘못됐거나, 20 MiB를 넘으면 400 에러를 반환한다
9. 중단·종료된 그룹에서는 임시저장을 저장할 수 없다
   - 그룹이 `STOP`·`SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
10. 삭제된 카드·기록은 임시저장 대상이 될 수 없다
    - `cardId`가 이 그룹 카드가 아니면 400, 삭제된 카드·기록이면 400 에러를 반환한다
11. 그룹원만 임시저장을 저장할 수 있다
    - 그룹원이 아니면 403, 인증되지 않으면 401 에러를 반환한다
12. 경로의 그룹이 있어야 한다
    - 그룹이 없으면 404 에러를 반환한다
13. 커밋 후 R2 삭제가 실패해도 요청은 성공한다
    - 성공 응답을 유지하고 삭제 표시를 남겨 청소에서 다시 지운다. `NoSuchKey`는 삭제 성공, `NoSuchBucket`은 다시 처리할 대상이다
14. 같은 시각의 임시저장도 그대로 검증한다
    - 기존 `updatedAt`보다 1단위라도 이르면 409 에러를 반환하고 업로드 링크를 발급하지 않는다. 같은 시각이어도 대상·본문·연결 검증은 그대로 한다
15. 다른 그룹의 임시저장을 덮어쓰다 실패하면 모두 보존한다
    - 저장에 실패하면 기존 임시저장과 두 그룹의 파일 연결을 그대로 둔다. 다른 기록에도 연결된 파일은 덮어써도 지우지 않는다
16. DB 처리가 실패하면 모두 되돌린다
    - 트랜잭션 도중 실패하면 기존 임시저장·파일 연결·업로드 기록을 그대로 두고, R2 객체는 지우지 않는다
17. 거부된 요청은 아무것도 바꾸지 않는다
    - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다
