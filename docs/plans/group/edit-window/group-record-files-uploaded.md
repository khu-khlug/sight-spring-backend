# 기록 첨부 파일 업로드 완료

기록 작성·수정이나 임시저장 저장 응답으로 받은 업로드 링크로 파일을 올린 뒤, 업로드를 마친 파일들을 서버에 알립니다. 서버는 파일마다 검증해 업로드 완료 표시를 남깁니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
POST /groups/:groupId/records/files/uploaded
```

## 권한

USER and 그룹원

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함. 중단 상태에서도 실행하며 그룹 상태는 바꾸지 않음
- `fileIds`가 비어 있지 않아야 함. 같은 아이디가 중복되면 하나로 처리하고, 결과도 서로 다른 아이디의 최초 등장 순서로 하나씩 반환함

### 파일 검증 흐름 (`fileIds`의 각 항목)

파일마다 아래 순서로 검증하고 결과를 따로 기록한다. 한 파일의 실패가 다른 파일의 처리를 막지 않는다.

1. 업로드 기록이 없음 — 실패 `NOT_FOUND`
2. 이 그룹의 기록 첨부 파일로 발급된 업로드 기록이 아님 — 실패 `NOT_FOUND`
3. 발급자가 요청자가 아님 — 실패 `FORBIDDEN`
4. 삭제 표시가 있음 — 실패 `DELETED`
5. R2에 객체가 없음 — 실패 `NOT_UPLOADED`. 업로드 기록은 지우지 않으며, 다시 업로드한 뒤 재요청할 수 있음
6. 이미 업로드 완료 표시가 있음 — 성공 (변경 없음)
7. 모두 통과 — 업로드 완료 표시를 남기고 성공

## 요청 바디

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `fileIds` | 문자열 배열 | 필수. 업로드를 마친 백엔드 파일 아이디 목록 |

## 성공 응답

모든 파일이 성공하면 200, 일부만 성공하면 206을 반환한다. 본문 형식은 같다.

```
200 OK
206 Partial Content
```

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `results` | 객체 배열 | 파일별 처리 결과. 요청 순서대로 |
| `results.fileId` | 문자열 | 백엔드 파일 아이디 |
| `results.isSuccess` | 불리언 | 업로드 완료 표시가 남았는지 |
| `results.reason` | 문자열 \| null | 실패 사유. `NOT_FOUND`, `FORBIDDEN`, `DELETED`, `NOT_UPLOADED`. 성공이면 null |

## 실패 응답

[그룹 공통 실패 응답](../global.md#공통-실패-응답)을 함께 적용한다.

| 상황 | 응답 코드 |
| :-- | :--: |
| 종료된 그룹임 | 400 |
| `fileIds`가 없거나 비어 있음 | 400 |
| 모든 파일이 실패함. 본문은 성공 응답과 같은 `results` | 400 |

## 테스트 케이스

1. 그룹원은 업로드를 마친 기록 첨부 파일을 알릴 수 있다
   - 본인이 이 그룹 기록 첨부용으로 발급받아 R2에 올린 파일 아이디를 보내면 업로드 완료 표시를 남긴다
   - 모두 성공하면 200 응답과 함께 파일마다 `isSuccess: true`·`reason: null`을 반환한다
2. 일부만 성공하면 206, 모두 실패하면 400을 반환한다
   - 세 경우 모두 같은 `results` 구조로 파일별 결과를 반환한다
   - 한 파일이 실패해도 나머지 파일은 처리한다
3. 파일마다 정해진 순서로 검증하고 실패 사유를 반환한다
   - 업로드 기록이 없거나 이 그룹 기록 첨부용이 아니면 `NOT_FOUND`, 발급자가 다르면 `FORBIDDEN`, 삭제 표시가 있으면 `DELETED`, R2에 객체가 없으면 `NOT_UPLOADED`다
   - 여러 조건에 걸리면 앞선 단계의 사유를 반환한다
4. 업로드되지 않은 파일은 올린 뒤 다시 알릴 수 있다
   - `NOT_UPLOADED`여도 업로드 기록을 지우지 않으므로, 파일을 올리고 다시 요청하면 성공한다
5. 이미 완료 표시가 있는 파일은 그대로 성공이다
   - 앞선 검증을 통과하면 변경 없이 성공으로 반환한다
6. 같은 아이디는 한 번만 처리한다
   - `fileIds=[A, A, B]`면 A를 한 번 처리하고 A, B 순서로 결과를 반환한다
7. `fileIds`는 비어 있지 않은 문자열 배열이어야 한다
   - 없거나 빈 배열이거나 문자열 배열이 아니면 400 에러를 반환한다
8. 중단된 그룹에서도 알릴 수 있다
   - 중단 그룹에서도 처리하며 그룹 상태는 바뀌지 않는다
9. 종료된 그룹에서는 알릴 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
10. 그룹원만 알릴 수 있다
    - 그룹원이 아니면 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
11. 거부된 요청은 아무것도 바꾸지 않는다
    - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다
