# 카드 기록 수정

작성한 기록의 본문을 수정합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
PATCH /groups/:groupId/records/:recordId
```

## 권한

USER and 그룹원 and 기록 작성자

## 조건

- 기록의 현재 소속 카드는 `recordId`로 조회하며, 해당 카드의 그룹이 `groupId`와 일치해야 함
- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- 카드가 삭제되지 않은 활성 상태여야 함. [카드 활성 상태별 동작](../card-window/group-card-disabled-update.md#비활성-상태의-동작)을 따름
- 삭제된 기록이 아니어야 함
- `TIPTAP` 기록이어야 함. `LEGACY` 기록은 읽기만 가능하며 수정할 수 없음
- 본문(`content`)이 빈 문자열이 아니고, UTF-8 바이트 기준 최대 1 MiB(1,048,576바이트)여야 함
- 첨부 파일 배열(`files`)은 [기록 첨부 파일](../global.md#기록-첨부-파일)의 비교 규칙을 따름. 비교 대상은 이 기록의 연결 목록임

## 저장 처리

- 작성 일시와 작성자는 유지하고, 본문이나 연결 목록이 실제로 변경되면 `updatedAt`을 갱신한다.
- `files` 배열로 이 기록의 연결 목록을 갱신한다. 새 파일은 업로드 링크를 발급하고, 배열에서 빠진 연결은 해제하며, 연결이 하나도 남지 않은 파일은 삭제한다.
- 수정이 성공하면 요청자의 임시저장을 지운다. [기록 첨부 파일의 임시저장과 기록 저장 사이의 처리](../global.md#임시저장과-기록-저장-사이의-처리)를 따른다.

## 요청 바디

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `content` | 문자열 | 필수. TIPTAP 문서 JSON을 직렬화한 문자열 |
| `files` | 객체 배열 | 필수. 본문이 참조하는 파일 전체. 형식은 [요청의 파일 식별자 배열](../global.md#요청의-파일-식별자-배열)을 따름 |

## 성공 응답

```
200 OK
```

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `uploads` | 객체 배열 | 새 파일의 업로드 정보. 새 파일이 없으면 빈 배열. 형식은 [기록 첨부 파일의 비교 규칙](../global.md#비교-규칙)을 따름 |

## 실패 응답

[그룹 공통 실패 응답](../global.md#공통-실패-응답)을 함께 적용한다.

| 상황 | 응답 코드 |
| :-- | :--: |
| 종료된 그룹임 | 400 |
| 비활성 카드임 | 400 |
| 본문이 빈 문자열이거나 1 MiB를 초과함 | 400 |
| `LEGACY` 기록을 수정하려 함 | 400 |
| `files` 형식이 잘못됨 (필수 값 누락, 식별자 중복, 최대 크기 초과) | 400 |
| 이미 연결된 식별자에 다른 `fileId`를 보냄 | 400 |
| `files`가 다른 그룹의 파일이나 존재하지 않거나 삭제된 파일을 참조함 | 400 |
| 삭제된 카드·기록임 | 404 |
