# 접수중인 활동보고 취소

제출한 활동보고를 취소합니다. 제출한 파일도 함께 삭제됩니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
DELETE /groups/:groupId/activity-reports/:reportId
```

## 권한

USER and (그룹장 or 운영진)

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- 해당 활동보고에 연결된 세미나의 `schedule.endAt`이 지나지 않았어야 함

## 부수 효과

### 그룹 상태

실제 변경이 발생하면 중단 상태를 진행 중으로 자동 전환한다. [그룹 공통 사항](../global.md#활동에-따른-중단-상태-해제)을 따른다.


### 경험치 변동

| 행동        | 포인트 | 대상      |
| ----------- | ------ | --------- |
| 세미나 발표 등록 취소 | -150 | 멤버 전체 |
| 보고서 제출 취소·삭제 | -150 | 멤버 전체 |

ExPoint 변동 시 멤버별로 `members.expoint` 직접 UPDATE + `expoint_log` INSERT 처리.

- 세미나 발표와 보고서 모두 제출 취소·삭제 시 멤버 전체에게 -150 exp를 적용한다. 운영진이 세미나 세션을 강제로 제거할 때도 같은 차감 기준을 적용한다.

### 알림

그룹 멤버 전체 + 운영진에게 알림 발송

### 그룹 활동 로그

그룹 활동 로그에 활동보고 취소를 기록하고 최근 활동 일시를 갱신함

## 실패 응답

| 상황                                          | 응답 코드 |
| :-------------------------------------------- | :-------: |
| 접수 기간(`schedule.endAt`)이 지난 활동보고임 |    400    |

## 테스트 케이스

1. 존재하지 않는 `reportId` 요청 → 404
2. 접수 기간(`schedule.endAt`)이 지난 활동보고 취소 요청 → 400
3. 그룹원(비그룹장, 비운영진) 삭제 요청 → 403
4. 그룹장이 삭제 요청 → 204
5. 운영진이 삭제 요청 → 204
6. 삭제 성공 시
   - `group_activity_report` row DELETE와 보고 파일의 업로드 기록 삭제 표시를 한 트랜잭션에서 처리
   - 커밋 후 [파일 삭제 흐름](../global.md#삭제-흐름)에 따라 R2 파일을 지우고, 성공하면 업로드 기록 삭제
   - 세미나 발표·보고서 모두 그룹원 전원 -150 exp
   - 그룹 멤버 전체 + 운영진에게 알림 발송

## 관련 DB 테이블

| 테이블                  | 역할                                                |
| ----------------------- | --------------------------------------------------- |
| `group`                 | 그룹 존재 확인 + `master` 컬럼으로 그룹장 여부 확인 |
| `group_activity_report` | 활동보고 DELETE                                     |
| `big_seminar`+`schedule`| 접수 기간 내 여부 확인 (`schedule.endAt`)           |
| `file_upload`        | 해당 파일 row DELETE                                |
| `group_member`          | 전체 멤버 목록 조회 (ExPoint 일괄 처리 시 사용)     |
| `members`               | `expoint` 직접 UPDATE                               |
| `expoint_log`           | ExPoint 변동 이력 INSERT                            |
