# 접수중인 활동보고 수정

이미 제출한 활동보고의 유형(보고서/세미나 발표)이나 파일을 바꿉니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
PATCH /groups/:groupId/activity-reports/:reportId
```

## 권한

USER and 그룹장

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- 해당 활동보고에 연결된 세미나의 `schedule.endAt`이 현재보다 나중이어야 함 (정각부터 접수 종료)
- `isPresentation`, `fileUploadId` 중 하나 이상 전송해야 함
- `fileUploadId`를 전송하면 아래 파일 검증 흐름을 통과해야 함

## 파일 검증 흐름 (`fileUploadId` 변경 시)

1. `file_upload`에서 `id = fileUploadId` row 조회 — 없으면 400
2. `api_path != "/groups/:groupId/activity-reports/upload-link"` — 400
3. `memberId != 요청자` — 400
4. `isUploaded == true` (이미 사용된 key) — 400
5. 이미 삭제 처리된 파일 (삭제 대기 중이라 R2에는 아직 남아 있을 수 있음) — 400
6. R2에 해당 key 파일 미존재 — row 삭제 후 400 (파일이 없으면 row도 유효하지 않음)
7. 모두 통과 → 기존 파일 삭제 표시 + `isUploaded = true` 설정 후 진행. 기존 R2 파일은 커밋 후 [파일 삭제 흐름](../global.md#삭제-흐름)으로 지움 (`fileKey`는 `file_upload.fileKey` 사용)

## 부수 효과

### 그룹 상태

실제 변경이 발생하면 중단 상태를 진행 중으로 자동 전환한다. [그룹 공통 사항](../global.md#활동에-따른-중단-상태-해제)을 따른다.


### 경험치 변동

(해당 없음)

### 알림

- `isPresentation`만 실제 변경 → 그룹 멤버 전체 + 운영진에게 발표 여부 변경 알림
- `fileUploadId`만 전송 → 그룹 멤버 전체 + 운영진에게 제출 파일 변경 알림
- 둘 다 실제 변경 → 그룹 멤버 전체 + 운영진에게 발표 여부 및 제출 파일 변경 알림. 발표 여부가 같고 파일만 바뀌면 파일 변경 알림만 보냄

### 그룹 활동 로그

그룹 활동 로그에 활동보고 수정을 기록하고 최근 활동 일시를 갱신함

## 쿼리스트링

(해당 없음)

## 요청 바디

| 이름             | 타입               | 기본값          | 설명                               |
| ---------------- | ------------------ | --------------- | ---------------------------------- |
| `isPresentation` | boolean (nullable) | null(변경 안 함) | false=보고서, true=세미나 발표     |
| `fileUploadId`   | 문자열 또는 null | null(변경 안 함) | 파일 변경 시 전송                  |

## 성공 응답

```
200 OK
```

| 이름             | 타입      | 설명                            |
| ---------------- | --------- | ------------------------------- |
| `id`             | 문자열 | `group_activity_report.id`      |
| `groupId`        | 숫자(Long) | group.id                        |
| `seminarId`      | 문자열 | big_seminar.id                  |
| `isPresentation` | boolean   | 발표 여부                       |
| `reportFileKey`  | string    | 보고 파일 key                   |
| `createdAt`      | string    | 생성 일시 (ISO 8601 UTC, `Z` 접미사) |
| `updatedAt`      | string    | 변경 일시 (ISO 8601 UTC, `Z` 접미사) |

## 실패 응답

| 상황                                                   | 응답 코드 |
| :----------------------------------------------------- | :-------: |
| 접수 기간(`schedule.endAt`)이 지난 활동보고임          |    400    |
| `isPresentation`, `fileUploadId` 모두 null/미전송      |    400    |
| `fileUploadId`가 파일 검증 흐름을 통과하지 못함        |    400    |
| 종료된 그룹임 | 400 |
| 보고서가 없거나 경로 그룹에 속하지 않음, 세미나/스케줄 참조 없음 | 404 |

## 리소스 소속·접수 경계

대상 보고서는 경로 그룹에 속해야 하며 다른 그룹의 보고서는 404다. 접수 가능 구간은 `현재 < schedule.endAt`이다. 정각부터 400으로 거부한다. 세미나 또는 스케줄 참조가 없으면 404다.

## 테스트 케이스

1. 그룹장은 접수 중인 활동보고의 유형을 바꿀 수 있다
   - 현재와 다른 `isPresentation`만 보내면 200 응답과 함께 유형만 바꾸고 파일은 그대로다
   - 그룹원 전체와 운영진에게 발표 여부 변경 알림을 보낸다
2. 제출 파일을 바꿀 수 있다
   - `fileUploadId`만 보내면 파일 검증을 통과한 새 파일로 바꾸고 유형은 그대로다. 기존 파일은 삭제 표시 후 커밋하고 R2에서 지운다
   - 그룹원 전체와 운영진에게 제출 파일 변경 알림을 보낸다
3. 유형과 파일을 함께 바꿀 수 있다
   - 둘 다 실제로 바뀌면 발표 여부·제출 파일 변경 알림을 함께 보낸다. 유형이 같고 파일만 바뀌면 파일 변경 알림만 보낸다
4. 수정은 경험치를 바꾸지 않는다
   - 활동보고 수정 로그를 남기고 최근 활동 일시를 갱신하며, 경험치는 그대로다
5. 바꿀 값이 하나 이상 있어야 한다
   - `isPresentation`과 `fileUploadId`가 모두 없거나 null이면 400 에러를 반환한다
6. 현재와 같은 유형만 보내면 아무것도 바뀌지 않는다
   - 200 응답을 반환하고 `updatedAt`·알림·로그를 바꾸지 않는다
7. 새 파일은 파일 검증 흐름을 통과해야 한다
   - 업로드 기록이 없거나, 발급 경로·발급자가 다르거나, 이미 사용됐거나, 삭제 표시가 있으면 400 에러를 반환한다. 다른 그룹에서 발급받은 파일도 400이다
   - R2에 객체가 없으면 그 업로드 기록을 지우고 400 에러를 반환한다. 기존 파일은 그대로다
8. 접수 기간이 지난 활동보고는 수정할 수 없다
   - `schedule.endAt` 정각부터 400 에러를 반환한다
9. 종료된 그룹에서는 수정할 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
10. 중단된 그룹에서 수정하면 그룹이 다시 진행 중이 된다
    - 실제로 바뀌면 그룹 상태가 `PROGRESS`로 전환된다
11. 그룹장만 수정할 수 있다
    - 그룹장이 아니면 일반 그룹원·운영진이어도 403, 인증되지 않으면 401 에러를 반환한다
12. 경로의 그룹·활동보고가 있어야 한다
    - 그룹이 없거나, 활동보고가 없거나 다른 그룹의 것이거나, 연결된 세미나·일정이 없으면 404 에러를 반환한다
13. 커밋 후 R2 삭제가 실패해도 요청은 성공한다
    - 성공 응답을 유지하고 삭제 표시를 남겨 청소에서 다시 지운다. `NoSuchKey`는 삭제 성공, `NoSuchBucket`은 다시 처리할 대상이다
14. 파일 검증에 실패하면 기존 데이터를 보존한다
    - 기존 보고서와 파일은 그대로 두고, R2 객체가 없는 해당 업로드 기록만 지운다. 상관없는 업로드는 지우지 않는다
15. 응답 필드는 정해진 타입이다
    - `id`·`seminarId`는 문자열, `groupId`는 숫자(Long), `isPresentation`은 불리언, 생성·수정 일시는 UTC ISO 8601 `Z` 형식이다
16. DB 처리가 실패하면 모두 되돌린다
    - 트랜잭션 도중 실패하면 활동보고·파일 사용 상태·알림·로그·그룹 상태를 함께 되돌리고, R2 객체는 지우지 않는다
17. 거부된 요청은 아무것도 바꾸지 않는다
    - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다

## 관련 DB 테이블

| 테이블                  | 역할                                                |
| ----------------------- | --------------------------------------------------- |
| `group`                 | 그룹 존재 확인 + `master` 컬럼으로 그룹장 여부 확인 |
| `group_activity_report` | 활동보고 조회 및 UPDATE                             |
| `big_seminar`+`schedule`| 접수 기간 내 여부 확인 (`schedule.endAt`)           |
| `file_upload`           | 파일 검증 + `isUploaded` UPDATE (`fileUploadId` 변경 시) |
