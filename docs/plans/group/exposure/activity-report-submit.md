# 활동보고 제출

접수 중인 세미나에 그룹의 활동보고(보고서 또는 세미나 발표)를 제출합니다. 파일은 먼저 업로드 링크 발급 API로 올린 뒤 `fileUploadId`로 연결합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
POST /groups/:groupId/activity-reports
```

## 권한

USER and 그룹장

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- 현재보다 `schedule.endAt`이 더 나중인 `big_seminar`가 있어야 함
- 보고서(`isPresentation=false`) 또는 세미나 발표(`isPresentation=true`) 중 하나 선택
- 파일 제출 필수
- `fileUploadId`가 아래 파일 검증 흐름을 통과해야 함

### 파일 검증 흐름 (`fileUploadId`)

1. `file_upload`에서 `id = fileUploadId` row 조회 — 없으면 400
2. `api_path != "/groups/:groupId/activity-reports/upload-link"` — 400
3. `memberId != 요청자` — 400
4. `isUploaded == true` (이미 사용된 key) — 400
5. 이미 삭제 처리된 파일 (삭제 대기 중이라 R2에는 아직 남아 있을 수 있음) — 400
6. R2에 해당 key 파일 미존재 — row 삭제 후 400 (파일이 없으면 row도 유효하지 않음)
7. 모두 통과 → `isUploaded = true` 설정 후 진행 (`fileKey`는 `file_upload.fileKey` 사용)

## 부수 효과

### 그룹 상태

실제 변경이 발생하면 중단 상태를 진행 중으로 자동 전환한다. [그룹 공통 사항](../global.md#활동에-따른-중단-상태-해제)을 따른다.


### 경험치 변동

| 행동          | 포인트 | 대상      |
| ------------- | ------ | --------- |
| 세미나 발표 등록(`isPresentation=true`) | +150 | 멤버 전체 |
| 보고서 제출(`isPresentation=false`) | +150 | 멤버 전체 |

ExPoint 변동 시 멤버별로 `members.expoint` 직접 UPDATE + `expoint_log` INSERT 처리.

- 세미나 발표와 보고서 모두 제출 시 멤버 전체에게 +150 exp를 지급한다.

### 알림

그룹 멤버 전체 + 운영진에게 알림 발송

### 그룹 활동 로그

그룹 활동 로그에 활동보고 제출을 기록하고 최근 활동 일시를 갱신함

## 쿼리스트링

(해당 없음)

## 요청 바디

| 이름              | 타입    | 설명                                         |
| ----------------- | ------- | -------------------------------------------- |
| `isPresentation`  | boolean | false=보고서, true=세미나 발표               |
| `fileUploadId`    | 문자열 | 업로드 링크 발급 시 받은 `file_upload.id`    |

## 성공 응답

```
201 Created
```

| 이름             | 타입      | 설명                              |
| ---------------- | --------- | --------------------------------- |
| `id`             | 문자열 | 생성된 `group_activity_report.id` |
| `groupId`        | 숫자(Long) | 제출한 그룹                       |
| `seminarId`      | 문자열 | 해당하는 세미나                   |
| `isPresentation` | boolean   | 발표 여부                         |
| `reportFileKey`  | string    | R2 파일 key                       |
| `createdAt`      | string    | 생성 일시 (ISO 8601 UTC, `Z` 접미사) |
| `updatedAt`      | string    | 변경 일시 (ISO 8601 UTC, `Z` 접미사) |

## 실패 응답

| 상황                                                    | 응답 코드 |
| :------------------------------------------------------ | :-------: |
| 접수 중인 세미나(`schedule.endAt`이 현재보다 나중)가 없음 |    400    |
| `fileUploadId`가 없거나 파일 검증 흐름을 통과하지 못함   |    400    |
| 종료된 그룹임 | 400 |
| 같은 그룹·같은 세미나에 이미 보고서가 있음 | 400 |

## 제출 대상과 중복 방지

접수 중인 세미나는 `schedule.endAt > 현재`인 일정에 연결된 세미나 중 `scheduledAt` 오름차순으로 선택한다. 동률이면 일정 아이디 오름차순으로 선택한다. 세미나가 없는 일반 일정은 건너뛴다.

같은 그룹·같은 세미나의 보고서는 하나만 허용한다. 다른 새 파일을 보내도 기존 보고서가 있으면 400이며 교체는 수정 API로 한다. 동시 제출에도 이 유일성과 경험치 한 번 지급을 보장한다. 보고서 저장·파일 사용·경험치 이력·알림·활동 로그·중단 해제는 한 트랜잭션으로 처리한다.

## 테스트 케이스

1. 그룹장은 접수 중인 세미나에 보고서를 제출할 수 있다
   - `isPresentation: false`와 `fileUploadId`를 보내면 201 응답과 함께 활동보고를 만들고 업로드 완료 표시를 남긴다
   - 그룹원 전체에게 +150 exp를 지급하고, 그룹원 전체와 운영진에게 알림을 보낸다
   - 활동보고 제출 로그를 남기고 최근 활동 일시를 갱신한다
2. 세미나 발표로도 제출할 수 있다
   - `isPresentation: true`면 세미나 발표로 저장하며 경험치·알림은 보고서와 같다
3. 접수 중인 세미나 중 가장 이른 것에 제출한다
   - `schedule.endAt`이 지금보다 뒤인 세미나 중 개최 시각이 가장 이른 것을 고르고, 같으면 일정 아이디 순이다. 세미나가 없는 일반 일정은 건너뛴다
   - 접수 중인 세미나가 없으면 400 에러를 반환한다. 마감 정각부터는 접수 중이 아니다
4. 같은 세미나에는 한 번만 제출할 수 있다
   - 이미 제출했으면 다른 파일로 보내도 400 에러를 반환한다. 동시에 요청해도 한 번만 만들고 경험치도 한 번만 준다
5. 제출 파일은 파일 검증 흐름을 통과해야 한다
   - `fileUploadId`가 없거나, 업로드 기록이 없거나, 발급 경로·발급자가 다르거나, 이미 사용됐거나, 삭제 표시가 있으면 400 에러를 반환한다
   - 다른 그룹에서 발급받은 파일은 발급 경로가 달라 400이다
   - R2에 객체가 없으면 그 업로드 기록을 지우고 400 에러를 반환한다
6. `isPresentation`은 불리언이어야 한다
   - 없거나 null이거나 불리언이 아니면 400 에러를 반환한다
7. 종료된 그룹에서는 제출할 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
8. 중단된 그룹에서 제출하면 그룹이 다시 진행 중이 된다
   - 그룹 상태가 `PROGRESS`로 전환된다
9. 그룹장만 제출할 수 있다
   - 그룹장이 아니면 일반 그룹원·운영진이어도 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
10. 파일 검증에 실패하면 기존 데이터를 보존한다
    - 기존 보고서와 파일은 그대로 두고, R2 객체가 없는 해당 업로드 기록만 지운다. 상관없는 업로드는 지우지 않는다
11. 응답 필드는 정해진 타입이다
    - `id`·`seminarId`는 문자열, `groupId`는 숫자(Long), `isPresentation`은 불리언, 생성·수정 일시는 UTC ISO 8601 `Z` 형식이다
12. DB 처리가 실패하면 모두 되돌린다
    - 트랜잭션 도중 실패하면 활동보고·파일 사용 상태·경험치와 경험치 이력·알림·로그·그룹 상태를 함께 되돌리고, R2 객체는 지우지 않는다
13. 거부된 요청은 아무것도 바꾸지 않는다
    - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다

## 관련 DB 테이블

| 테이블                  | 역할                                                        |
| ----------------------- | ----------------------------------------------------------- |
| `group`                 | 그룹 존재 확인 + `master` 컬럼으로 그룹장 여부 확인         |
| `big_seminar`+`schedule`| 현재로부터 가장 가까운 세미나 존재 여부 확인 (`schedule.endAt`) |
| `file_upload`           | 파일 검증 + `isUploaded` UPDATE                             |
| `group_activity_report` | 활동보고 INSERT                                             |
| `group_member`          | 전체 멤버 목록 조회 (ExPoint 일괄 처리 시 사용)             |
| `members`               | `expoint` 직접 UPDATE                                       |
| `expoint_log`           | ExPoint 변동 이력 INSERT                                    |
