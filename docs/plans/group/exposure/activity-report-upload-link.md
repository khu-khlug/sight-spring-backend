# 활동보고 파일 업로드 링크 발급

활동보고 파일을 올릴 업로드 주소(Presigned URL)를 발급합니다. 발급한 `url`로 파일 업로드를 완료한 뒤 `fileUploadId`를 활동보고 제출·수정 요청에 포함해야 합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
POST /groups/:groupId/activity-reports/upload-link
```

## 권한

USER and 그룹장

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함. 중단 상태에서는 발급하며 그룹 상태는 바꾸지 않음. [업로드 링크 발급의 중단 상태 예외](../global.md#중단-상태에서의-동작-제한)를 따름

## 제한

- 업로드 파일 최대 크기: [업로드 링크 기준](../global.md#업로드-링크-기준)을 따름 (Presigned URL 생성 시 `content-length-range` 조건으로 R2 단에서 강제)

## 부수 효과

(해당 없음)

## 쿼리스트링

(해당 없음)

## 요청 바디

(해당 없음)

## 성공 응답

```
200 OK
```

| 이름             | 타입   | 설명                              |
| ---------------- | ------ | --------------------------------- |
| `url`            | string | R2 Presigned URL. 유효 시간은 [업로드 링크 기준](../global.md#업로드-링크-기준)을 따름 |
| `fileKey`            | string | R2 object key                     |
| `fileUploadId` | 문자열 | `file_upload.id`               |


## 설계 결정: 공용 API 대신 개별 API로 분리한 이유

공용 Presigned URL API(`POST /files/presigned-url`)로 만들면 인증된 사용자라면 누구나 어떤 용도로든 key를 발급받을 수 있어 아래 두 가지 문제가 생긴다:

1. **key 용도 검증 불가**: 활동보고 제출 시 `reportFileKey`가 실제로 활동보고용으로 발급된 것인지 확인할 수 없다. 다른 API에서 발급받은 key를 가져다 쓰는 것을 막을 방법이 없다.

2. **권한 분리 불가**: 활동보고 업로드는 그룹장만 가능한데, 공용 API에 이 권한을 적용하면 다른 용도의 업로드도 함께 제한된다.

개별 API로 분리하면 `api_path` 컬럼에 발급 경로를 저장해두고, 활동보고 제출·수정 시 해당 key가 이 API에서 발급된 것인지 검증할 수 있다. R2 업로드 내부 함수는 재사용하되 API 진입점만 분리하는 방식이다.

## 발급 실패 처리

R2 서명 발급 실패는 502, DB 저장·예약 등록 실패는 500이다. 업로드 기록과 지속 가능한 확인 예약의 등록은 함께 성공하거나 함께 취소되어야 하며, 실패한 링크는 응답하지 않는다. 실제 파일 업로드는 후속 클라이언트 요청이므로 링크 발급 실패가 다른 파일을 삭제하지 않는다.

## 테스트 케이스

1. 그룹장은 활동보고 파일 업로드 링크를 발급받을 수 있다
   - 200 응답과 함께 `url`·`fileKey`·`fileUploadId`를 반환한다
   - 발급자와 그룹 아이디가 들어간 발급 경로를 담아 미사용 업로드 기록을 만든다
2. 업로드 링크는 정해진 기준을 따른다
   - PUT URL은 10분간 유효하고, 링크 만료 시각에 1분을 더한 시점에 업로드 확인을 예약한다
   - 20 MiB까지 올릴 수 있고 20 MiB를 넘으면 저장소에서 거부한다
3. 업로드되지 않은 파일은 확인 예약 시점에 정리한다
   - 미사용 파일의 R2 객체가 없으면 삭제 표시 후 업로드 기록을 정리한다. 객체가 있으면 미사용 업로드로 유지하고 주기적 청소 대상 규칙을 따른다. 이미 제출된 파일은 정리하지 않는다
4. 발급에 실패하면 링크를 주지 않는다
   - R2 서명 실패는 502, DB 저장·예약 등록 실패는 500 에러를 반환하며, 업로드 기록과 예약을 반쯤 남기지 않는다
5. 중단된 그룹에서도 발급할 수 있다
   - 중단 그룹에서도 200 응답을 반환하며 그룹 상태는 바뀌지 않는다
6. 종료된 그룹에서는 발급할 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
7. 그룹장만 발급받을 수 있다
   - 그룹장이 아니면 일반 그룹원·운영진이어도 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
8. 거부된 요청은 아무것도 바꾸지 않는다
   - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다. R2 서명·업로드 기록·확인 예약도 만들지 않는다
