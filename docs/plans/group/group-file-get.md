# 그룹 파일 조회

그룹 파일의 영구 주소에서 열람 권한을 확인하고 임시 읽기 주소로 이동합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
GET /groups/:groupId/files/:fileId
```

## 권한

USER and 열람권한

## 조건

- 파일의 실제 소속 그룹이 `groupId`와 일치해야 함. 소속은 서버의 파일 연결 정보로 판정함
- `fileId`는 업로드 기록의 문자열 아이디이며 R2 객체 키가 아님
- 업로드 완료 상태이고 삭제 표시가 없어야 함
- 그룹 열람 권한으로 제공할 수 있는 파일이어야 함. 더 강한 권한이 필요한 파일은 각 기능 API에서 별도로 처리함. 활동보고는 기존 조회 API에서 임시 읽기 주소를 직접 반환함
- 그룹 중단·종료와 카드 비활성 여부는 파일 열람을 제한하지 않음

## 부수 효과

권한 검사 후 파일별 Presigned GET URL 캐시를 사용한다. `read_url`·`read_url_expires_at`이 없거나 만료까지 1분 이하이면 7일 유효 URL을 발급해 갱신한다. 캐시 재사용에도 권한 검사를 생략하지 않는다. 파일 제공 정책이 바뀌면 캐시를 무효화한다.

## 요청 바디

(해당 없음)

## 성공 응답

```
302 Found
```

응답 본문은 없다.

| 헤더 | 값 | 설명 |
| :-- | :-- | :-- |
| `Location` | Presigned GET URL | 브라우저가 파일을 받을 임시 읽기 주소 |
| `Cache-Control` | `private, no-store` | 리다이렉션 응답을 캐싱하지 않음 |

파일 응답 헤더는 [공통 파일 제공 기준](global.md#파일-제공-헤더)을 따른다.

영구 주소는 매 요청 권한을 확인하지만 이미 발급된 Presigned URL은 만료까지 재사용 가능하다. 권한 변경이 이미 발급한 URL을 즉시 폐기하는 것은 아니다.

## 실패 응답

[그룹 공통 실패 응답](global.md#공통-실패-응답)을 함께 적용한다.

| 상황 | 응답 코드 |
| :-- | :--: |
| 인증 없음 | 401 |
| 그룹 열람 권한 없음 | 403 |
| 그룹·파일 없음, 다른 그룹 파일, 별도 권한으로 보호되는 파일, 삭제·미완료·객체 없음 | 404 |
| 경로 아이디 형식 오류 | 400 |
| 스토리지 요청 실패 | 502 |

## 테스트 케이스

1. 열람 권한이 있는 회원은 그룹 파일을 조회할 수 있다
   - 302 응답의 `Location`으로 Presigned GET URL을 반환하고 본문은 반환하지 않는다
   - 작성자·임시저장 소유자 여부 등의 추가 권한은 검사하지 않는다
2. 공개 범위에 따라 열람할 수 있는 회원이 정해진다
   - 그룹원은 공개 범위와 관계없이 요청할 수 있다. 비그룹원은 그룹 공통 VIEWER 정책을 따른다
   - 열람 권한이 없으면 403, 인증되지 않으면 401이다. URL 캐시가 있어도 동일하게 검사한다
3. 별도 권한이 필요한 파일은 제공하지 않는다
   - 활동보고 등 별도 권한의 파일은 같은 그룹이어도 404다. 그룹 파일 경로로 권한 검사를 우회할 수 없다
4. 그룹과 파일이 유효해야 한다
   - 그룹·파일 없음, 다른 그룹 파일, 삭제·미완료 파일 또는 R2 객체 없음은 404다
   - 경로 아이디 형식 오류는 400, 스토리지 요청 실패는 502다
5. 임시 읽기 주소를 캐싱한다
   - 유효한 캐시는 재사용하고 없거나 만료까지 1분 이하이면 재발급한다
   - 응답에 `Cache-Control: private, no-store`를 설정한다
6. 그룹 상태와 관계없이 조회할 수 있다
   - 중단·종료 그룹과 비활성 카드에서도 열람 권한이 있으면 제공한다
   - 파일 조회로 그룹 활동 상태·경험치·로그를 바꾸지 않는다
