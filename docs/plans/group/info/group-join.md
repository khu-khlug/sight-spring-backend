# 그룹 참가

요청자가 그룹에 그룹원으로 참가합니다. 신청·승인 절차 없이 즉시 그룹원이 됩니다.

## 운영 그룹인 경우

- 참가 알림을 그룹장 대신 그룹 멤버 전체에게 보냄

## API 경로

```
POST /groups/:groupId/members/@me
```

## 권한

USER and 열람권한

## 조건

- 요청자가 그룹원이 아니어야 함
- 그룹의 참여 신청 가능 여부(`allowJoin`)가 켜져 있어야 함
- 그룹 상태가 진행 중 또는 중단이어야 함. 종료된 그룹에는 참가할 수 없음

## 부수 효과

### 그룹 상태

실제 변경이 발생하면 중단 상태를 진행 중으로 자동 전환한다. [그룹 공통 사항](../global.md#활동에-따른-중단-상태-해제)을 따른다.


### 경험치 변동

| 대상      | 변동 |
| :-------- | :--: |
| 참가 회원 | +40  |

### 알림

요청자에게 참가 확인 알림, 그룹장에게 참가 알림. 운영(`MANAGE`) 그룹이면 그룹장 대신 그룹 멤버 전체에게 알림

### 그룹 활동 로그

그룹 활동 로그에 멤버 참가를 기록하고 최근 활동 일시를 갱신함

## 실패 응답

| 상황                                     | 응답 코드 |
| :--------------------------------------- | :-------: |
| 요청자가 이미 그룹원임                   |    400    |
| 참여 신청 가능 여부(`allowJoin`)가 꺼져 있음 |    403    |
| 그룹 열람 권한이 없음 | 403 |
| 종료된 그룹임 | 400 |
| 존재하지 않는 그룹임 | 404 |

## 테스트 케이스

1. 열람 권한이 있는 회원은 그룹에 참가할 수 있다
   - 201 응답과 함께 그룹원이 되고 그룹원 수를 1 늘린다. 참가자에게 +40 exp를 지급한다
   - 참가자와 그룹장에게 알림을 보낸다. 운영(`MANAGE`) 그룹이면 그룹장 대신 그룹원 전체에게 보낸다
   - 멤버 참가 로그를 남기고 최근 활동 일시를 갱신한다
2. 이미 그룹원이면 참가할 수 없다
   - 400 에러를 반환한다. 동시에 요청해도 한 번만 참가한다
3. 참여 신청이 켜진 그룹에만 참가할 수 있다
   - `allowJoin`이 꺼져 있으면 403 에러를 반환한다
4. 종료된 그룹에는 참가할 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
5. 중단된 그룹에 참가하면 그룹이 다시 진행 중이 된다
   - 그룹 상태가 `PROGRESS`로 전환된다
6. 열람 권한이 있어야 참가할 수 있다
   - 공개 범위 밖 회원이면 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
7. DB 처리가 실패하면 모두 되돌린다
   - 트랜잭션 도중 실패하면 회원 관계·그룹장·그룹원 수·경험치와 경험치 이력·알림·로그·중단 해제를 함께 되돌린다
8. 거부된 요청은 아무것도 바꾸지 않는다
   - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다
