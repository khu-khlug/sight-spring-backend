# 그룹 리스트 순서 변경

같은 그룹 안에서 리스트의 표시 위치를 변경합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
PATCH /groups/:groupId/lists/:listId/position
```

경로의 `listId`는 위치를 변경할 리스트다.

## 권한

USER and 그룹원

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- 경로의 리스트(`listId`)가 이 그룹의 리스트여야 함
- 기준 리스트(`insertBeforeListId`)를 지정하면 같은 그룹의 리스트여야 함
- 자기 자신을 기준으로 지정하거나 결과 순서가 같으면 변경 없이 성공함

## 부수 효과

### 그룹 상태

실제 변경이 발생하면 중단 상태를 진행 중으로 자동 전환한다. [그룹 공통 사항](../global.md#활동에-따른-중단-상태-해제)을 따른다.

### 경험치 변동

그룹 활동 로그는 기록하지 않음. 실제 변경 시 최근 활동 일시만 갱신함

## 요청 바디

| 이름 | 타입 | 설명 |
| :-- | :--: | :-- |
| `insertBeforeListId` | 문자열 | 선택. 이 리스트 바로 앞에 삽입. 생략하거나 null이면 맨 끝 |

## 성공 응답

```
204 No Content
```

(해당 없음)

## 실패 응답

[그룹 공통 실패 응답](../global.md#공통-실패-응답)을 함께 적용한다.

| 상황 | 응답 코드 |
| :-- | :--: |
| 종료된 그룹임 | 400 |
| 기준 리스트가 같은 그룹에 존재하지 않음 | 400 |
| 경로의 리스트가 이 그룹에 없음 | 404 |

## 테스트 케이스

1. 그룹원은 리스트 순서를 바꿀 수 있다
   - `insertBeforeListId`를 보내면 204 응답과 함께 그 리스트 바로 앞으로 옮긴다
   - 로그는 남기지 않고 최근 활동 일시만 갱신한다
2. 기준 리스트를 생략하면 맨 끝으로 간다
   - `insertBeforeListId`를 생략하거나 null로 보내면 맨 끝으로 옮긴다
3. 순서가 그대로면 아무것도 바뀌지 않는다
   - 자기 자신을 기준으로 지정하거나 결과 순서가 같으면 204 응답을 반환하고 최근 활동 일시를 바꾸지 않는다
4. 기준 리스트는 이 그룹에 있어야 한다
   - 기준 리스트가 이 그룹에 없으면 400 에러를 반환한다
5. 종료된 그룹에서는 순서를 바꿀 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
6. 중단된 그룹에서 순서를 바꾸면 그룹이 다시 진행 중이 된다
   - 실제로 순서가 바뀌면 그룹 상태가 `PROGRESS`로 전환된다
7. 그룹원만 순서를 바꿀 수 있다
   - 그룹원이 아니면 403, 인증되지 않으면 401 에러를 반환한다
8. 경로의 그룹·리스트가 있어야 한다
   - 그룹이 없거나, 리스트가 없거나 다른 그룹의 리스트면 404 에러를 반환한다
9. 거부된 요청은 아무것도 바꾸지 않는다
   - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다
