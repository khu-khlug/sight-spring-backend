# 그룹장 위임

그룹장이 다른 멤버에게 그룹장을 위임합니다. 위임 후 요청자는 일반 그룹원이 됩니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
PUT /groups/:groupId/leader
```

## 권한

USER and 그룹장

## 조건

- 그룹이 종료(`SUCCESS`·`FAIL`) 상태가 아니어야 함
- 대상(`userId`)이 그룹 멤버여야 함
- 대상이 요청자 본인이 아니어야 함

## 부수 효과

### 그룹 상태

실제 변경이 발생하면 중단 상태를 진행 중으로 자동 전환한다. [그룹 공통 사항](../global.md#활동에-따른-중단-상태-해제)을 따른다.


### 경험치 변동

(해당 없음)

### 알림

그룹 멤버 전체에게 그룹장 변경 알림

### 그룹 활동 로그

그룹 활동 로그에 그룹장 위임을 기록하고 최근 활동 일시를 갱신함

## 쿼리스트링

(해당 없음)

## 요청 바디

| 이름     |  타입  | 설명                       |
| :------- | :----: | :------------------------- |
| `userId` | 숫자(Long) | 새 그룹장이 될 회원 아이디 |

## 성공 응답

```
204 No Content
```

(해당 없음)

## 실패 응답

| 상황                     | 응답 코드 |
| :----------------------- | :-------: |
| 종료된 그룹임            |    400    |
| 대상이 그룹 멤버가 아님  |    400    |
| 대상이 요청자 본인임     |    400    |
| 요청자가 그룹장이 아님   |    403    |
| 존재하지 않는 그룹임    |    404    |
| 존재하지 않는 회원임    |    404    |

## 입력 검증

`userId`는 필수 숫자(Long)이며 누락·null·정수가 아닌 값·Long 범위 초과는 400이다. 위임 후 이전 그룹장은 위임 권한을 잃는다.

## 테스트 케이스

1. 그룹장은 다른 그룹원에게 그룹장을 위임할 수 있다
   - `userId`를 보내면 204 응답과 함께 그룹장이 그 회원으로 바뀌고, 요청자는 일반 그룹원이 된다
   - 그룹원 전체에게 그룹장 변경 알림을 보내고, 그룹장 위임 로그를 남기고 최근 활동 일시를 갱신한다
2. 위임한 뒤에는 위임할 수 없다
   - 이전 그룹장이 같은 요청을 다시 보내면 403 에러를 반환한다
3. 위임 대상은 요청자가 아닌 그룹원이어야 한다
   - 대상 회원이 그룹원이 아니거나 요청자 본인이면 400 에러를 반환한다
   - 대상 회원이 없으면 404 에러를 반환한다
4. `userId`는 숫자(Long)여야 한다
   - 없거나 null이거나 문자열·소수이거나 Long 범위를 넘으면 400 에러를 반환한다
5. 종료된 그룹에서는 위임할 수 없다
   - 그룹이 `SUCCESS`·`FAIL` 상태면 400 에러를 반환한다
6. 중단된 그룹에서 위임하면 그룹이 다시 진행 중이 된다
   - 그룹 상태가 `PROGRESS`로 전환된다
7. 그룹장만 위임할 수 있다
   - 그룹장이 아니면 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
8. DB 처리가 실패하면 모두 되돌린다
   - 트랜잭션 도중 실패하면 회원 관계·그룹장·그룹원 수·경험치와 경험치 이력·알림·로그·중단 해제를 함께 되돌린다
9. 거부된 요청은 아무것도 바꾸지 않는다
   - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다
