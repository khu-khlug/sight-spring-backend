# 그룹 저장소 커밋 목록 조회

요청한 브랜치의 전체 커밋 이력을 최신 커밋부터 조회합니다. 다른 브랜치와 공유하는 조상 커밋과 병합 커밋도 포함됩니다.

공용 GitHub 토큰의 사용자별 호출량은 [저장소 API 공통 사항](global.md)을 따릅니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
GET /groups/:groupId/repository/commits
```

## 권한

USER and 열람권한

## 조건

- `url`이 그룹에 등록된 저장소 URL(`repositoryUrls`) 중 하나여야 함
- `branch`가 해당 저장소에 있는 브랜치여야 함

## 제한

- 한 번에 받는 커밋 수는 30개로 고정함. 남은 이력이 30개 미만이면 남은 개수만 반환하며, 추가 이력은 `page`를 1씩 늘려 다시 요청해야 함. 개수를 지정하는 옵션은 받지 않음
- 백엔드에 30개보다 많은 이력이 캐시되어 있어도 요청한 범위만 반환함
- 조회 시작 위치는 `page × 30`임. GitHub에는 `page + 1`, `per_page=30`으로 요청함

## 부수 효과

공용 토큰의 GitHub 기본 호출 한도를 실제로 소모한 경우에만 원인 사용자의 시간당 할당량을 차감함. 인증된 조건부 GET의 `304`는 차감하지 않음. 캐시 재검증과 공통 fetcher의 호출 제어는 [공통 사항](global.md)을 따름.

## 쿼리스트링

| 이름         |    타입    | 기본값                   | 설명                                  |
| :----------- | :--------: | :----------------------: | :------------------------------------ |
| `url` | 문자열 | 없음(필수) | 그룹에 등록된 저장소 URL. 쿼리 값 인코딩은 [공통 사항](global.md)을 따름 |
| `branch` | 문자열 | 없음(필수) | 커밋을 조회할 브랜치 이름. 쿼리 값 인코딩은 [공통 사항](global.md)을 따름 |
| `page`       | 숫자(uint) |            0             | 0부터 시작하는 페이지 번호. `0`은 첫 30개, `1`은 다음 30개 |
| `refresh` | 불리언 | `false` | `true`이면 캐시 유효기간과 무관하게 조건부 GET으로 재검증. [공통 사항](global.md) 참고 |

## 요청 바디

(해당 없음)

## 성공 응답

```
200 OK
```

| 이름                  |    타입    | 설명                                                       |
| :-------------------- | :--------: | :--------------------------------------------------------- |
| `page`                | 숫자(uint) | 반환한 페이지 번호 (요청의 `page`와 같음) |
| `receivedCount`       | 숫자(uint) | 받은 커밋 수 (`commits` 길이)                              |
| `hasMore`             |   불리언   | 이보다 이전 커밋이 더 있는지                               |
| `commits`             | 객체 배열  | 커밋 목록. 최신 커밋이 앞                                  |
| `commits.sha`         |   문자열   | 커밋 SHA                                                   |
| `commits.message`     |   문자열   | 커밋 메시지 전체. HTML로 해석하지 않는 일반 텍스트 |

## 실패 응답

| 상황                                           | 응답 코드 |
| :--------------------------------------------- | :-------: |
| `url`이 그룹에 등록된 저장소가 아님            |    400    |
| 쿼리 파라미터의 `url` 또는 `branch`가 없거나 비어 있음 | 400 |
| `branch`가 저장소에 없음     |    404    |
| `page`가 0 이상의 정수가 아님 | 400 |
| 저장소 서비스 요청 한도를 넘었거나 응답이 실패함 |    502    |
| 실제 GitHub 호출이 필요하지만 원인 사용자의 시간당 100회 할당량이 소진됨 | 429 |
| `refresh`가 `true`·`false`가 아님 | 400 |
| 같은 저장소에 1분 안에 `refresh=true`를 10번 넘게 요청함 | 429 |

## 설계 결정

- 공통 조상과의 거리만으로는 최초 분기 방향을 확정할 수 없고 병합·리베이스로 추정 결과가 달라질 수 있다. 잘못 추정한 분기점에서 이력이 누락되는 것을 피하기 위해 전체 이력을 조회한다.
- 30개 고정 단위로만 조회하므로 임의의 건너뛸 개수보다 조회 단위를 직접 나타내는 `page`를 사용한다.
- 캐시가 누적될수록 같은 요청의 응답 크기가 커지는 것을 방지하기 위해 캐시 보관 범위와 응답 범위를 분리한다.
