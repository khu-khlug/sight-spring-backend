# 그룹 저장소 파일 트리 조회

요청한 커밋 시점의 파일·디렉터리 경로 목록을 조회합니다. 커밋 대신 브랜치를 지정하면 그 브랜치의 끝(HEAD) 커밋을 대상으로 조회합니다.

공용 GitHub 토큰의 사용자별 호출량은 [저장소 API 공통 사항](global.md)을 따릅니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
GET /groups/:groupId/repository/file-tree
```

## 권한

USER and 열람권한

## 조건

- `url`이 그룹에 등록된 저장소 URL(`repositoryUrls`) 중 하나여야 함
- `branch`와 `commitSha` 중 정확히 하나만 보내야 함
- `commitSha`를 보내면 해당 저장소에 있는 커밋이어야 함
- `branch`를 보내면 해당 저장소에 있는 브랜치여야 함

## 대상 커밋 결정

- `commitSha`를 보내면 그 커밋을 대상으로 한다.
- `branch`를 보내면 그 브랜치의 끝 커밋을 대상으로 한다. 끝 커밋은 [브랜치 커밋 캐시](global.md#브랜치-커밋-캐시)의 0페이지 첫 커밋으로 정하며, 캐시가 없거나 유효기간이 지났으면 공통 규칙대로 조회·재검증한다.
- 대상 커밋이 정해진 뒤의 파일 트리 조회와 캐시는 `commitSha`를 보낸 경우와 같다.

## 제한

- 저장소 서비스가 한 번에 돌려줄 수 있는 항목 수를 넘으면 일부만 반환하고 `truncated`를 true로 표시함
  - GitHub 트리 API는 재귀 조회 시 최대 100,000개 항목, 7MB까지만 반환함

## 새니타이징

- `commitSha`는 16진수 문자(7~40자)만 허용한다.
- `branch`는 원문 값으로 받으며, 인코딩은 [공통 사항의 쿼리 값 인코딩](global.md#쿼리-값-인코딩)을 따른다.

## 부수 효과

공용 토큰의 GitHub 기본 호출 한도를 실제로 소모한 경우에만 원인 사용자의 시간당 할당량을 차감함. 인증된 조건부 GET의 `304`는 차감하지 않음. 캐시 재검증과 공통 fetcher의 호출 제어는 [공통 사항](global.md)을 따름.

## 쿼리스트링

| 이름        |  타입  | 설명          |
| :---------- | :----: | :------------ |
| `url`       | 문자열 | 저장소 URL    |
| `commitSha` | 문자열 | 대상 커밋 SHA. `branch`와 둘 중 하나만 보냄 |
| `branch` | 문자열 | 대상 브랜치 이름. 그 브랜치의 끝 커밋을 대상으로 함. `commitSha`와 둘 중 하나만 보냄 |
| `refresh` | 불리언 | 생략 가능, 기본값 `false`. 파일 트리 캐시는 영구라 재검증하지 않음. `branch`로 요청하면 `true`일 때 끝 커밋을 결정하는 브랜치 커밋 캐시를 재검증함. [공통 사항](global.md) 참고 |

## 요청 바디

(해당 없음)

## 성공 응답

```
200 OK
```

| 이름              |      타입      | 설명                                                                        |
| :---------------- | :------------: | :-------------------------------------------------------------------------- |
| `commitSha`       |     문자열     | 조회한 커밋 SHA. `branch`로 요청했으면 결정된 끝 커밋 SHA                   |
| `truncated`       |     불리언     | 항목이 너무 많아 일부만 반환했는지                                          |
| `entries`         |   객체 배열    | 경로 목록                                                                   |
| `entries.path`    |     문자열     | 저장소 루트 기준 경로                                                       |
| `entries.type`    |      enum      | `file`(파일) \| `dir`(디렉터리)                                            |
| `entries.rawUrl`  | 문자열 \| null | 파일 원문을 바로 받을 수 있는 주소. `file`일 때만 있고 `dir`이면 null      |

### 파일 원문 주소

`entries.rawUrl`은 저장소 서비스의 원문 주소(GitHub이면 `https://raw.githubusercontent.com/...`)로만 만든다.

## 실패 응답

| 상황                                           | 응답 코드 |
| :--------------------------------------------- | :-------: |
| `url`이 그룹에 등록된 저장소가 아님            |    400    |
| `branch`와 `commitSha`를 둘 다 보냈거나 둘 다 보내지 않음 |    400    |
| `commitSha`가 저장소에 없음                    |    404    |
| `branch`가 저장소에 없음                       |    404    |
| GitHub 공용 토큰의 전체 한도가 소진됐거나 저장소 서비스 응답이 실패함 |    502    |
| 실제 GitHub 호출이 필요하지만 원인 사용자의 시간당 100회 할당량이 소진됨 | 429 |
| `refresh`가 `true`·`false`가 아님 | 400 |
| 같은 저장소에 1분 안에 `refresh=true`를 10번 넘게 요청함 | 429 |

## 테스트 케이스

1. 열람 권한이 있는 회원은 커밋 시점의 파일 트리를 조회할 수 있다
   - 등록된 저장소의 `commitSha`를 보내면 200 응답과 함께 그 커밋의 파일·디렉터리 경로를 반환한다
   - 파일은 `type: file`과 저장소 서비스의 원문 주소 `rawUrl`, 디렉터리는 `type: dir`과 `rawUrl: null`이다
   - 없는 커밋은 404, GitHub 실패는 502 에러를 반환한다
2. 브랜치를 보내면 그 브랜치의 끝 커밋을 조회한다
   - `branch`를 보내면 브랜치 커밋 캐시의 0페이지 첫 커밋을 대상으로 하고, 응답 `commitSha`에 그 SHA를 담는다
   - 끝 커밋은 1분 브랜치 커밋 캐시를 따른다. 만료되거나 `refresh=true`면 0페이지를 재검증하고, 200이면 새 끝 커밋의 트리를 조회한다
   - 없는 브랜치는 404 에러를 반환한다
3. `branch`와 `commitSha` 중 하나만 보내야 한다
   - 둘 다 보내거나 둘 다 없으면 400 에러를 반환한다
   - `commitSha`는 7~40자 16진수만 허용하고, 6자·41자·16진수가 아닌 값은 400이다
4. 트리 일부만 받으면 그렇다고 표시한다
   - GitHub가 일부만 주면 `truncated: true`와 받은 항목만 반환한다. 항목이 없으면 `entries`는 빈 배열이다
5. 커밋 SHA로 정해진 트리는 영구 캐시한다
   - 트리 캐시는 재검증하지 않으며 `refresh=true`여도 트리는 다시 조회하지 않는다. 캐시에서 밀려난 뒤에는 다시 조회한다
6. 한 요청에서 여러 번 호출할 때도 한도를 확인한다
   - 호출이 두 번 필요한데 잔여량이 1회면 첫 호출만 보내고 429 에러를 반환한다. 이미 차감한 1회는 되돌리지 않는다
7. 사용자별 한도는 원인 사용자의 시간당 100회다
   - 그룹·저장소·API 종류가 달라도 합산한다. 동시 요청은 미리 예약해 100회를 넘지 않는다
   - 99회 쓴 사용자의 한 번은 허용하고, 100회를 쓴 뒤 외부 호출이 필요하면 GitHub에 보내지 않고 429 에러를 반환한다. 캐시만으로 응답할 수 있으면 200이다
8. 캐시 응답과 인증된 304는 사용자 한도를 차감하지 않는다
   - 200·오류·재시도는 GitHub 기본 한도를 실제로 소모한 횟수만 원인 사용자에게 차감하고, 보내지 않았거나 304인 예약은 해제한다
   - 동시 재검증을 하나로 합치면 실제 원인 사용자 한 명에게만 차감한다
9. 공용 토큰의 전체 한도가 소진되면 502다
   - 공용 사용량 4,999회에서 마지막 1회는 허용하고, 5,000회 뒤에는 GitHub에 보내지 않고 502 에러를 반환한다
10. 같은 저장소의 `refresh=true`는 1분에 10번까지다
    - 10번째까지 허용하고 11번째는 GitHub를 호출하지 않고 429 에러를 반환한다. 다른 저장소의 횟수와는 따로 센다
11. 모든 GitHub 호출은 공통 fetcher를 거친다
    - 동시 10개·초당 5회 제한을 여러 인스턴스가 함께 쓰며 304에도 적용한다. `Retry-After`·잔여량·초기화 시각과 403·429를 반영해 재시도한다
12. 조건부 GET으로 재검증한다
    - ETag가 있으면 `If-None-Match`, ETag 없이 Last-Modified만 있으면 `If-Modified-Since`를 보내고, 둘 다 없으면 일반 GET을 보낸다. 인증 정보는 항상 보낸다
    - 304면 저장한 본문으로 200 응답을 만들고 유효기간을 갱신한다. 오류는 캐시에 저장하지 않고 유효기간도 늘리지 않는다
13. 캐시는 1,000행까지 보관한다
    - 조회할 때마다 마지막 조회 시각을 갱신하고, 1,001번째 행이 들어오면 마지막 조회가 가장 오래된 행을 교체한다
14. 등록된 저장소와 올바른 쿼리만 처리한다
    - 등록되지 않은 `url`, 필수 값 누락, `true`·`false`가 아닌 `refresh`는 400 에러를 반환하고 GitHub를 호출하지 않는다
    - 원문 URL·브랜치명을 다시 디코딩하거나 이중 인코딩하지 않고, GitHub 요청 형식에 맞게 인코딩한다
15. 그룹 상태와 관계없이 조회할 수 있다
    - 중단·종료 그룹에서도 열람 권한이 있으면 200 응답을 반환한다
16. 공개 범위에 따라 조회할 수 있는 회원이 정해진다
    - 비공개는 그룹원, 운영진 공개는 운영진, 회원 공개는 교류 회원을 제외한 회원, 완전 공개는 모든 로그인 회원이 조회할 수 있다
    - 범위 밖 회원이면 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환하며 GitHub를 호출하지 않는다
17. 조건이 다른 캐시는 섞지 않는다
    - 다른 저장소·커밋·조회 조건·인증 범위의 본문이나 검증자를 섞어 쓰지 않는다
