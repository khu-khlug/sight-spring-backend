# 그룹 내 검색

그룹 안의 카드명, 카드 생성자명, 기록 본문을 키워드로 검색합니다. 삭제된 카드와 삭제된 기록은 제외하고, 비활성 카드는 포함합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
GET /groups/:groupId/search
```

## 권한

USER and 열람권한

## 조건

- `keyword`가 공백이 아니어야 함

## 제한

- `keyword` 길이는 최대 20자
- 결과는 한 페이지에 50개씩 나눠 반환하며, 다른 페이지는 `page`를 바꿔 다시 요청해야 함

## 정렬

- `RECORD`는 기록의 `updated_at` 내림차순, `TITLE`·`AUTHOR`는 카드의 `updated_at` 내림차순으로 정렬한다.
- `updated_at`이 같으면 아이디 내림차순으로 정렬한다.
- 카드의 최근 변경에는 기록 추가·삭제로 인한 `count_record` 변경도 포함한다.

## 검색 방식

- `LIKE '%검색어%'`로 검색하며 검색용 인덱스(MySQL `FULLTEXT` 등)는 현재 추가하지 않는다.
- `keyword`는 SQL 문자열에 직접 이어 붙이지 않고 파라미터로 바인딩한다.
- `keyword` 안의 `LIKE` 와일드카드(`%`, `_`)와 이스케이프 문자(`\`)는 이스케이프해 글자 그대로 검색되게 한다.

## 설계 결정

- 50개 고정 단위의 조회 위치를 직접 지정할 수 있도록 건수 단위 오프셋 대신 `page`를 사용한다.
- 추가 페이지 조회에 필요한 호출 횟수를 줄이기 위해 한 번에 50개를 반환한다.
- 레거시의 `updated_at`은 행 변경과 카드의 기록 수 변경 시에도 갱신되므로 기록 추가·삭제를 포함한 최근 변경의 기준으로 사용한다. 같은 시각의 결과도 순서가 고정되도록 아이디를 보조 정렬 기준으로 사용한다.
- 선행 와일드카드가 있는 `LIKE` 검색은 일반 인덱스로 검색 범위를 줄이기 어렵다. 검색용 인덱스의 필요성은 실제 성능 문제가 확인된 뒤 판단한다.

## 부수 효과

## 쿼리스트링

| 이름      |    타입    | 기본값 | 설명                                                                 |
| :-------- | :--------: | :----: | :------------------------------------------------------------------- |
| `target`  |    enum    |   -    | 검색 대상. `TITLE`(카드명) \| `AUTHOR`(카드 생성자명) \| `RECORD`(기록 본문) |
| `keyword` |   문자열   |   -    | 검색어. 대소문자를 구분하지 않음                                     |
| `page`    | 숫자(uint) |   1    | 1부터 시작하는 페이지 번호. `page`번째 50개 결과를 반환              |

## 요청 바디

(해당 없음)

## 성공 응답

```
200 OK
```

| 이름                  |      타입      | 설명                                                                                          |
| :-------------------- | :------------: | :-------------------------------------------------------------------------------------------- |
| `page`                |   숫자(uint)   | 반환한 페이지 번호 (요청의 `page`와 같음)                                                      |
| `totalPages`          |   숫자(uint)   | 검색 결과의 전체 페이지 수. 결과가 없으면 0                                                    |
| `receivedCount`       |   숫자(uint)   | 받은 결과 수 (`results` 길이)                                                                 |
| `results`             |   객체 배열    | 검색 결과 목록. 최근 변경순(정렬 참고) |
| `results.listId`      |     문자열     | 카드가 속한 리스트 아이디                                                                     |
| `results.listTitle`   |     문자열     | 카드가 속한 리스트 제목                                                                       |
| `results.cardId`      |     문자열     | 카드 아이디                                                                                   |
| `results.cardTitle`   |     문자열     | 카드명                                                                                        |
| `results.recordId`    | 숫자(Long) \| null | 일치한 기록 아이디. `target`이 `RECORD`일 때만 있고 나머지는 null                              |
| `results.matchedText` | 문자열 \| null | 일치한 부분 미리보기. `RECORD`면 본문 일부, `AUTHOR`면 생성자명, `TITLE`이면 null              |

### 미리보기 생성

`RECORD`의 `matchedText`는 기록 본문(TIPTAP JSON·레거시 HTML)에서 태그와 마크업을 제거한 일반 텍스트로 만들어 반환한다.

## 실패 응답

| 상황                           | 응답 코드 |
| :----------------------------- | :-------: |
| 검색어가 비어 있거나 너무 김   |    400    |
| `page`가 1보다 작음            |    400    |

## 테스트 케이스

1. 열람 권한이 있는 회원은 카드명으로 검색할 수 있다
   - `target=TITLE`이면 200 응답과 함께 카드명이 일치한 결과를 반환한다. `recordId`와 `matchedText`는 null이다
2. 카드 생성자명으로 검색할 수 있다
   - `target=AUTHOR`면 카드 생성자명이 일치한 결과를 반환한다. `matchedText`는 생성자명이며 담당자명은 검색하지 않는다
3. 기록 본문으로 검색할 수 있다
   - `target=RECORD`면 일치한 기록 아이디와 본문 미리보기를 반환한다. 미리보기는 TIPTAP JSON·레거시 HTML에서 마크업을 뺀 일반 텍스트다
4. 각 결과에는 카드와 리스트 정보가 있다
   - 리스트 아이디·제목, 카드 아이디·카드명을 반환한다. 다른 그룹의 결과는 포함하지 않는다
5. 삭제된 카드·기록은 검색하지 않는다
   - 삭제된 카드와 기록, 삭제된 카드의 기록은 빼고, 비활성 카드는 포함한다
6. 검색어는 글자 그대로 찾는다
   - 대소문자를 구분하지 않는다. `%`, `_`, `\`는 와일드카드가 아닌 글자로 찾고, 검색어는 파라미터로 바인딩한다
7. 검색어는 공백이 아닌 20자 이하여야 한다
   - 20자는 허용하고, 없거나 공백뿐이거나 21자면 400 에러를 반환한다. `target`이 없거나 허용하지 않는 값이어도 400이다
8. 결과는 50개씩 페이지로 나눠 반환한다
   - `page`를 생략하면 1이다. 결과가 51개면 `totalPages`는 2이고 2페이지에 1개가 있다. 결과가 없으면 `totalPages`는 0이다
   - 전체 페이지를 넘는 요청은 빈 배열을 반환한다. `page`가 0·음수·소수·숫자가 아니면 400 에러를 반환한다
9. 결과는 최근 변경순으로 정렬한다
   - `RECORD`는 기록 수정 시각, `TITLE`·`AUTHOR`는 카드 수정 시각 내림차순이며, 같으면 아이디 내림차순이다
   - 기록 추가·삭제로 카드 수정 시각이 바뀌면 `TITLE`·`AUTHOR` 순서에도 반영된다
10. 그룹 상태와 관계없이 검색할 수 있다
    - 중단·종료 그룹에서도 열람 권한이 있으면 200 응답을 반환한다
11. 공개 범위에 따라 검색할 수 있는 회원이 정해진다
    - 비공개는 그룹원, 운영진 공개는 운영진, 회원 공개는 교류 회원을 제외한 회원, 완전 공개는 모든 로그인 회원이 검색할 수 있다
    - 범위 밖 회원이면 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
