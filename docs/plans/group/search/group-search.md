# 그룹 내 검색

그룹 안의 카드명, 카드 생성자명, 기록 본문을 키워드로 검색합니다. 삭제된 카드와 삭제된 기록은 제외하고, 비활성 카드는 포함합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
GET /groups/:groupId/search
```

## 권한

USER and 열람권한

## 조건

- `keyword`가 공백이 아니어야 함

## 제한

- `keyword` 길이는 최대 20자
- 결과는 한 페이지에 50개씩 나눠 반환하며, 다른 페이지는 `page`를 바꿔 다시 요청해야 함

## 정렬

- `RECORD`는 기록의 `updated_at` 내림차순, `TITLE`·`AUTHOR`는 카드의 `updated_at` 내림차순으로 정렬한다.
- `updated_at`이 같으면 아이디 내림차순으로 정렬한다.
- 카드의 최근 변경에는 기록 추가·삭제로 인한 `count_record` 변경도 포함한다.

## 검색 방식

- `keyword`를 공백(스페이스·탭·줄바꿈 등)으로 나누고 빈 항목과 중복 검색어를 제거한다. 모든 검색어가 대상 텍스트에 포함되어야 하는 AND 검색이다. 단어의 순서와 인접 여부는 제한하지 않는다.
- 대소문자를 구분하지 않는 단순 부분 문자열 검색을 사용한다. 예를 들어 `스프링 백엔드`는 `스프링`과 `백엔드`가 모두 있는 항목과 일치한다.
- `TITLE`은 카드명, `AUTHOR`는 카드 생성자명, `RECORD`는 아래 기준으로 추출한 기록의 표시 텍스트를 검색한다.
- 카드명, 생성자명에 SQL `LIKE`를 사용하면 검색어별 `LIKE '%검색어%'` 조건을 AND로 결합하고 파라미터로 바인딩한다. `%`, `_`, `\`는 이스케이프해 글자 그대로 찾는다.
- 형태소 분석·유사도·오타 교정·관련도 정렬 등 고급 검색과 검색용 인덱스(MySQL `FULLTEXT` 등)는 적용하지 않는다.
- 모든 검색어의 일치 여부를 판정한 결과를 기준으로 정렬·페이지네이션·전체 페이지 수를 계산한다.

### 기록 표시 텍스트 추출

- 레거시 HTML은 jsoup으로 파싱해 본문 텍스트를 추출하고 HTML 엔티티를 디코딩한다. 스크립트·스타일과 화면에 표시하지 않는 데이터는 제외한다.
- Tiptap JSON은 Jackson으로 파싱해 작성된 본문 텍스트를 읽는다. JSON 이스케이프는 파싱으로 해제하며, 직렬화된 JSON 원문을 검색하지 않는다.
- 인라인 서식으로 나뉜 텍스트는 그대로 이어 붙이고, 문단·목록 항목·표 셀·명시적 줄바꿈의 경계는 공백으로 구분한다. 연속된 공백은 하나로 정리한다.
- 구현 시 프런트의 `sight-frontend/src/components/BlockContent/extensions.ts`와 각 블록의 저장 형식·표시 코드를 확인해 커스텀 블록도 처리한다. 수식·코드·접기 블록·표 등에 저장된 본문 텍스트와 해당 필드를 확인하며, 일반 `text` 노드만 읽고 끝내지 않는다.
- 파일명(`fileAttachment.attrs.name` 등)·이미지 대체 텍스트(`alt`)·미디어 제목 등 첨부 메타데이터는 검색과 미리보기에서 제외한다. `type`·속성명·내부 식별자·파일 및 링크의 대상 URL도 검색하지 않는다. 파일명이나 URL을 일반 본문 텍스트로 직접 작성한 경우에는 검색한다.
- 저장된 HTML·JSON 원문은 유지하며 검색과 결과 미리보기에 같은 텍스트 추출 규칙을 적용한다.

## 설계 결정

- 50개 고정 단위의 조회 위치를 직접 지정할 수 있도록 건수 단위 오프셋 대신 `page`를 사용한다.
- 추가 페이지 조회에 필요한 호출 횟수를 줄이기 위해 한 번에 50개를 반환한다.
- 레거시의 `updated_at`은 행 변경과 카드의 기록 수 변경 시에도 갱신되므로 기록 추가·삭제를 포함한 최근 변경의 기준으로 사용한다. 같은 시각의 결과도 순서가 고정되도록 아이디를 보조 정렬 기준으로 사용한다.
- 선행 와일드카드가 있는 `LIKE` 검색은 일반 인덱스로 검색 범위를 줄이기 어렵다. 검색용 인덱스의 필요성은 실제 성능 문제가 확인된 뒤 판단한다.

## 쿼리스트링

| 이름      |    타입    | 기본값 | 설명                                                                 |
| :-------- | :--------: | :----: | :------------------------------------------------------------------- |
| `target`  |    enum    |   -    | 검색 대상. `TITLE`(카드명) \| `AUTHOR`(카드 생성자명) \| `RECORD`(기록 본문) |
| `keyword` |   문자열   |   -    | 공백으로 구분한 검색어. 모든 단어를 AND로 검색하며 대소문자를 구분하지 않음 |
| `page`    | 숫자(uint) |   1    | 1부터 시작하는 페이지 번호. `page`번째 50개 결과를 반환              |

## 요청 바디

(해당 없음)

## 성공 응답

```
200 OK
```

| 이름                  |      타입      | 설명                                                                                          |
| :-------------------- | :------------: | :-------------------------------------------------------------------------------------------- |
| `page`                |   숫자(uint)   | 반환한 페이지 번호 (요청의 `page`와 같음)                                                      |
| `totalPages`          |   숫자(uint)   | 검색 결과의 전체 페이지 수. 결과가 없으면 0                                                    |
| `receivedCount`       |   숫자(uint)   | 받은 결과 수 (`results` 길이)                                                                 |
| `results`             |   객체 배열    | 검색 결과 목록. 최근 변경순(정렬 참고) |
| `results.listId`      |     10진 문자열     | 카드가 속한 리스트 아이디                                                                     |
| `results.listTitle`   |     문자열     | 카드가 속한 리스트 제목                                                                       |
| `results.cardId`      |     10진 문자열     | 카드 아이디                                                                                   |
| `results.cardTitle`   |     문자열     | 카드명                                                                                        |
| `results.recordId`    | 10진 문자열 \| null | 일치한 기록 아이디. `target`이 `RECORD`일 때만 있고 나머지는 null                              |
| `results.matchedText` | 문자열 \| null | 일치한 부분 미리보기. `RECORD`면 본문 일부, `AUTHOR`면 생성자명, `TITLE`이면 null              |

### 미리보기 생성

`RECORD`의 `matchedText`는 검색에 사용한 표시 텍스트에서 일치 위치 주변을 잘라 반환한다. 여러 검색어가 멀리 떨어져 있으면 미리보기 한 조각에 모든 검색어가 포함될 필요는 없지만, 기록 전체는 AND 조건을 만족해야 한다.

## 실패 응답

| 상황                           | 응답 코드 |
| :----------------------------- | :-------: |
| 검색어가 비어 있거나 너무 김   |    400    |
| `page`가 1보다 작음            |    400    |

## 테스트 케이스

1. 열람 권한이 있는 회원은 카드명으로 검색할 수 있다
   - `target=TITLE`이면 200 응답과 함께 카드명이 일치한 결과를 반환한다. `recordId`와 `matchedText`는 null이다
2. 카드 생성자명으로 검색할 수 있다
   - `target=AUTHOR`면 카드 생성자명이 일치한 결과를 반환한다. `matchedText`는 생성자명이며 담당자명은 검색하지 않는다
3. 기록 본문으로 검색할 수 있다
   - `target=RECORD`면 추출한 표시 텍스트가 일치한 기록 아이디와 같은 텍스트에서 만든 본문 미리보기를 반환한다
   - HTML의 `<b>안녕</b>하세요`와 인라인 서식으로 나뉜 Tiptap 텍스트는 `안녕하세요`로 검색된다. HTML의 `A &amp; B`는 `&`로, JSON 문자열에 이스케이프된 따옴표·역슬래시·유니코드는 파싱 후의 실제 문자로 검색된다
   - 본문에 없는 `paragraph` 같은 노드 종류나 URL의 일부만 검색하면 일치하지 않는다. 다만 URL이 일반 본문 텍스트로 작성된 경우에는 일치한다
   - 파일명·이미지 대체 텍스트·미디어 제목에만 있는 단어로는 검색되지 않으며, 해당 메타데이터는 미리보기에도 포함되지 않는다. 같은 단어를 일반 본문 텍스트로 작성한 경우에는 검색된다
4. 각 결과에는 카드와 리스트 정보가 있다
   - 리스트 아이디·제목, 카드 아이디·카드명을 반환한다. 다른 그룹의 결과는 포함하지 않는다
5. 삭제된 카드·기록은 검색하지 않는다
   - 삭제된 카드와 기록, 삭제된 카드의 기록은 빼고, 비활성 카드는 포함한다
6. 검색어는 글자 그대로 찾는다
   - 대소문자를 구분하지 않는다. `%`, `_`, `\`는 와일드카드가 아닌 글자로 찾고, 검색어는 파라미터로 바인딩한다
   - `스프링 백엔드`는 두 단어가 순서와 관계없이 모두 있는 항목만 반환하며, 하나만 있으면 제외한다
   - 앞뒤 공백·연속 공백·탭·줄바꿈·같은 단어의 반복은 검색 결과를 바꾸지 않는다
7. 검색어는 공백이 아닌 20자 이하여야 한다
   - 20자는 허용하고, 없거나 공백뿐이거나 21자면 400 에러를 반환한다. `target`이 없거나 허용하지 않는 값이어도 400이다
8. 결과는 50개씩 페이지로 나눠 반환한다
   - `page`를 생략하면 1이다. 결과가 51개면 `totalPages`는 2이고 2페이지에 1개가 있다. 결과가 없으면 `totalPages`는 0이다
   - 전체 페이지를 넘는 요청은 빈 배열을 반환한다. `page`가 0·음수·소수·숫자가 아니면 400 에러를 반환한다
9. 결과는 최근 변경순으로 정렬한다
   - `RECORD`는 기록 수정 시각, `TITLE`·`AUTHOR`는 카드 수정 시각 내림차순이며, 같으면 아이디 내림차순이다
   - 기록 추가·삭제로 카드 수정 시각이 바뀌면 `TITLE`·`AUTHOR` 순서에도 반영된다
10. 그룹 상태와 관계없이 검색할 수 있다
    - 중단·종료 그룹에서도 열람 권한이 있으면 200 응답을 반환한다
11. 공개 범위에 따라 검색할 수 있는 회원이 정해진다
    - 그룹원은 공개 범위와 관계없이 요청할 수 있다. 비그룹원은 비공개에서 거부하며, 운영진 공개는 운영진, 회원 공개는 교류 회원을 제외한 회원, 완전 공개는 모든 로그인 회원이 검색할 수 있다
    - 범위 밖 회원이면 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
