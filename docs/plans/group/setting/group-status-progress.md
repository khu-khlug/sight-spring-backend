# 그룹 활동 재진행

종료되거나 중단된 그룹을 진행 상태로 변경합니다. 종료된 그룹은 종료 시 지급했던 경험치를 회수합니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```
PUT /groups/:groupId/status/progress
```

## 권한

USER and (그룹장 or 운영진)

## 조건

- 현재 상태가 종료(성공)(`SUCCESS`), 종료(실패)(`FAIL`) 또는 중단(`STOP`)이어야 함
- 종료 후 경과 시간에 따른 제한은 없음
- 중단된 그룹은 기존 규칙대로 그룹 내 활동 발생 시에도 자동으로 진행 상태로 복귀함. 종료된 그룹은 활동 발생만으로 자동 복귀하지 않음

## 부수 효과

### 그룹 상태

종료(`SUCCESS`·`FAIL`) 또는 중단(`STOP`, 현재 스프링의 `SUSPEND`) 상태를 진행 중(`PROGRESS`)으로 변경한다. 이 API의 명시적인 재진행은 다른 API의 활동에 따른 자동 중단 해제와 구분하며, 아래 경험치·알림·로그를 적용한다.

### 경험치 변동

| 변경 전 상태 | 대상 | 변동 |
| :-- | :-- | :--: |
| `SUCCESS` | 현재 멤버 전체 | -90 |
| `FAIL` | 현재 멤버 전체 | -70 |
| `STOP` | - | 없음 |

### 알림

현재 멤버 전체에게 그룹이 다시 진행 중임을 알림

### 그룹 활동 로그

그룹 활동 로그에 재진행을 기록하고 최근 활동 일시를 갱신함

## 실패 응답

| 상황 | 응답 코드 |
| :-- | :--: |
| 그룹장도 운영진도 아님 | 403 |
| 현재 상태가 `SUCCESS`·`FAIL`·`STOP`이 아님 | 400 |

이미 진행 중인 그룹에는 경험치를 다시 회수하거나 재진행 로그·알림을 중복 생성하지 않음

## 테스트 케이스

1. 그룹장이나 운영진은 성공 종료된 그룹을 다시 진행할 수 있다
   - 204 응답과 함께 `PROGRESS`로 바꾸고 현재 그룹원 전체에게 -90 exp를 적용한다
   - 현재 그룹원 전체에게 재진행 알림을 보내고, 재진행 로그를 남기고 최근 활동 일시를 갱신한다
2. 실패 종료된 그룹도 다시 진행할 수 있다
   - 204 응답과 함께 `PROGRESS`로 바꾸고 현재 그룹원 전체에게 -70 exp를 적용한다
3. 중단된 그룹도 다시 진행할 수 있다
   - 204 응답과 함께 `PROGRESS`로 바꾸며 경험치는 바뀌지 않는다
4. 경험치는 요청 시점의 그룹원에게 회수한다
   - 종료 후 경과 시간과 관계없이 다시 진행할 수 있고, 종료 당시가 아닌 지금 그룹원에게 회수한다
5. 이미 진행 중인 그룹은 다시 진행할 수 없다
   - 400 에러를 반환하며 경험치·알림·로그를 다시 남기지 않는다
6. 그룹장이나 운영진만 다시 진행할 수 있다
   - 둘 다 아니면 403, 인증되지 않으면 401, 그룹이 없으면 404 에러를 반환한다
7. 거부된 요청은 아무것도 바꾸지 않는다
   - 400·401·403·404 응답에서는 데이터와 경험치·알림·로그·최근 활동 일시·그룹 상태를 바꾸지 않는다
