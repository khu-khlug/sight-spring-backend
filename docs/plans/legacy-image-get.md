# 레거시 이미지 조회

기존 경로를 유지하고 Spring에서 Presigned GET URL로 리다이렉션한다. [제공 결정](../decisions/legacy-files.md)과 [이전 계획](file-migration.md)을 따른다.

## 운영 그룹인 경우

기존 파일의 실제 소속과 열람 정책을 따른다.

## API 경로

```text
GET /image/:filename
```

`filename`은 기존 `khlug_files.name`으로 조회한다. 사이트 전체의 레거시 파일을 대상으로 하며 신규 `file_upload`는 이 경로에서 조회하지 않는다.

## 권한

기존 `article`·`type` 등 소속 정보와 원본 제공 코드를 기준으로 원본 리소스의 파일 열람 권한을 검사한다. 기존 공개 파일은 공개 범위를 유지하고, 비공개 파일은 Spring 인증과 소속 리소스 권한을 검사한다. 키를 아는 것만으로 열람을 허용하지 않는다. 미확인 권한·소속은 임의로 공개하지 않으며 배포 전 이전 계획의 확인을 완료한다.

## 조건

- 기존 테이블의 메타데이터와 해당 R2 객체가 존재해야 한다. 신규 업로드의 완료·삭제 표시 컬럼은 적용하지 않는다.
- 기존 도메인의 같은 경로도 Caddy에서 Spring으로 라우팅한다. Laravel 호출은 하지 않는다.

## 부수 효과

권한 검사 후 `khlug_files.read_url`·`read_url_expires_at` 캐시를 사용한다. 캐시가 없거나 만료까지 1분 이하이면 7일 유효 Presigned GET URL을 발급해 두 컬럼을 갱신한다. 기존 `updated_at`은 유지하며 신규 `file_upload` 행은 만들지 않는다. 파일 다운로드 횟수 등 레거시 통계를 이번 전환에서 새로 집계하지 않는다.

## 쿼리스트링

신규 파라미터는 없다. 기존 변환·캐시 관련 쿼리의 의미는 실제 제공 코드를 확인해 이전 계획에서 검증한다. 임의 쿼리를 R2 서명 URL에 덧붙이지 않는다.

## 요청 바디

(해당 없음)

## 성공 응답

```text
302 Found
Location: <Presigned GET URL>
Cache-Control: private, no-store
```

응답 본문은 없다. 브라우저가 R2에서 파일을 받는다. 응답 헤더는 [공통 파일 제공 기준](group/global.md#파일-제공-헤더)을 따른다. 원본 HTML은 바꾸지 않는다.

## 실패 응답

| 상황 | 응답 코드 |
| :-- | :--: |
| 비공개 파일 요청에 인증 없음 | 401 |
| 원본 리소스 열람 권한 없음 또는 소속·권한 미확인 | 403 |
| 기존 메타데이터가 없거나 파일이 삭제됨, R2 객체 없음 | 404 |
| 스토리지 요청 실패 | 502 |

## 테스트 케이스

1. 기존 저장명으로 요청하면 동일 객체의 Presigned GET URL로 302 응답한다. 신규 파일의 키로는 404다.
2. 기존 HTML의 상대·절대 주소와 기존 도메인 요청이 Laravel 없이 같은 파일을 제공한다.
3. 비공개 파일은 매번 권한을 검사한다. URL 캐시가 있어도 권한 없는 요청은 거부한다.
4. URL 캐시가 유효하면 재사용하고 만료 전 안전 여유가 부족하면 재발급한다. 리다이렉션 응답은 캐싱하지 않는다.
5. 응답 헤더는 공통 파일 제공 기준을 따른다. 미확인 쿼리 동작은 이전 전에 확인한다.
6. 미존재·삭제·스토리지 실패를 구분하고 Range 요청 후 R2의 부분 응답과 미디어 탐색이 유지되는지 확인한다.
