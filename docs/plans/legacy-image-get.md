# 레거시 이미지 조회

기존 기록의 이미지 등을 기존 서버로 폴백하여 제공합니다. [레거시 파일·이미지 제공 결정](../decisions/legacy-files.md)을 따릅니다.

## 운영 그룹인 경우

(해당 없음)

## API 경로

```text
GET /image/:filename
```

`filename`은 레거시 이미지의 저장명이다. 기존 HTML과의 호환을 위해 단수형 경로와 저장명 식별자를 유지한다.

## 권한

기존 서버의 이미지 열람 권한 검사를 적용한다. 인증에 필요한 요청자의 쿠키를 기존 서버에 전달한다.

## 조건

- `app.khlug.org/image/:filename` 요청을 Spring 서버가 `https://khlug.org/image/:filename`로 전달한다.
- 기존 파일과 파일 메타데이터를 Spring 백엔드로 이전하지 않는다.

## 부수 효과

기존 서버의 이미지 조회 처리를 따른다.

## 쿼리스트링

추가 파라미터는 정의하지 않는다. 기존 URL에 포함된 쿼리스트링은 그대로 전달한다.

## 요청 바디

(해당 없음)

## 성공 응답

```text
200 OK
```

기존 서버가 반환한 이미지 본문과 응답 상태를 전달한다. `Content-Type`·`Content-Disposition` 등 이미지 제공에 필요한 응답 헤더를 유지하여 브라우저에서 표시한다.

## 실패 응답

| 상황 | 응답 코드 |
| :-- | :--: |
| 기존 서버가 인증·권한·이미지 없음 등의 오류를 반환함 | 기존 서버의 응답 코드와 본문 유지 |
| 기존 서버 연결 실패 또는 타임아웃 | 502 |

## 테스트 케이스

1. 기존 이미지 경로로 요청할 수 있다
   - `app.khlug.org/image/a.jpg` 요청을 기존 서버의 `/image/a.jpg`로 전달하고 이미지 응답을 반환한다.
2. 기존 서버의 인증·응답 계약을 유지한다
   - 요청자의 인증 쿠키와 쿼리스트링을 전달하고, 성공·권한 거부·이미지 없음 응답 및 이미지 MIME 헤더를 유지한다.
3. 연결 실패를 처리한다
   - 기존 서버 연결 실패나 타임아웃이면 502를 반환한다.
